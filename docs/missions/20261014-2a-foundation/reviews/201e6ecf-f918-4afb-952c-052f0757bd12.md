## Non-blocking issues (follow-ups for the Architect or owner)

- **N1. Detection gaps:** ANSI colour codes (e.g. `--color=yes`, `PY_COLORS=1`), CR-only line endings, and `pytest -q` without a banner all go undetected. Honest default runs that capture output (not a tty) are uncoloured, so these are hardening items, not bypasses of the owner rule. A worker who wants to cheat can delete assertions anyway; skip detection protects against honest skips caused by the environment.
- **N2. Surviving mutant M24 (marker without `re.M`):** both marker tests print the marker on line 1. Fix in the test only: print one line before the marker, for example in `test_stderr_skip_marker_fails_the_record`.
- **N3. `tests/run-tests.sh` hides child skips:** `check()` discards child output, so a skip inside the suite (for example `test-fleet-v2.py` without jsonschema) still records `pass` when the suite itself is the verification command. This was out of T-043's scope. Decide whether `check()` should fail a child that reports a skip.
- **N4. The pytest regex is quadratic on hostile lines:** a single line `= ` + `1 skipped `×N with no closing banner takes 3 s at about 200 KB and about 50 s at about 800 KB, and grows with N². The verifier has no per-command timeout, so this means a hang, not a pass (fail-closed for acceptance). Fix: bound the `[^\n]*` spans or match line by line.
- **N5. Bookkeeping:** PROGRESS says "7 commands" for record b0dbcaf5, but the task and the record have 6. `tasks/T-043.md` ends with a stray `=== END FILE ===` line left over from the Architect block.
- **N6. Process note for brain/Architect runs:** `python3 -I` ignores `PYTHONDONTWRITEBYTECODE`. My first probe imported a clone's `scripts/` under `-I` and wrote `__pycache__`, which made 7 bytecode/ledger checks fail in that clone's suite run. A fresh clone run passed. Never import repository modules under `-I` in a tree whose checks you then run.
