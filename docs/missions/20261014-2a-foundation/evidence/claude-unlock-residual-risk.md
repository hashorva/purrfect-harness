# Claude contract 9 residual risk

Contract 9 runs Claude Code with `--permission-mode bypassPermissions` and `--add-dir <repo>` so an unattended `-p` worker can make authorized changes without interactive approval. It also uses `--strict-mcp-config` to avoid starting unapproved MCP servers and `--disallowedTools` to block known destructive commands and protected-path edits. Headless mode does not provide an OS-level workspace-write sandbox. `acceptEdits` and `dontAsk` do not confine shell commands when `Bash` is enabled.

The two-layer guard combines a 73-pattern `--disallowedTools` deny-list with post-run state checks. `capture_before` keeps the protected baseline in memory (`_PROTECTED_BASELINES`), and `git_delta` compares against it while checking deletion or modification of `.tasks/specs/<run_id>.protected`. A symlinked `~/.claude` or `~/.claude/projects` root is recorded by its link target only, and allowlisted files are hashed through the link. The `~/.claude` snapshot uses an explicit configuration allowlist and ignores volatile runtime paths such as `sessions/` and `plugins/`. It also checks `.git/info/exclude` and `git ls-files -v` for skip-worktree or assume-unchanged flags. Any new or changed `__pycache__/` or compiled file outside `.tasks/` (`COMPILED_SUFFIXES`: the compiled entries of `importlib.machinery.all_suffixes()` plus `.pyo`, `.pyd`, `.so`, `.dylib`) is a scope violation that no ignore rule can hide; stdlib-named modules with any `importlib.machinery.all_suffixes()` suffix at the repo root, in `scripts/`, or in `tests/` are violations too. The persistence mechanisms named here are all snapshotted; no further path is named here.

The owner accepts this residual risk: `bypassPermissions` plus `Bash` remains an unsandboxed shell. A command that evades `--disallowedTools` can read, exfiltrate, or mutate paths outside the workspace. The post-run snapshot detects changes only to the explicitly listed protected paths and Git workspace/index state.
