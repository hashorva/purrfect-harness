## Why this task exists

T-001 attempt 1 stopped at its baseline. The worker ran the full test suite twice
at the same time (its first command outlived the tool's wait window, so it started a
second copy). `tests/test-verification-record.py` edits the live
`scripts/verification_record.py` to break one guard, runs a focused test, then restores
the file. A second process that read the file during that window saw a broken guard
and failed. The failure is not a sandbox limit: the suite passes under the Codex
sandbox when run once. A kill during the mutation would also leave the real script
broken. Tests must never change the live tree.
