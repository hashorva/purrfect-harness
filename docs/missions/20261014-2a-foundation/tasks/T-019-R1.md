## Objective

**Why this task exists.** T-019's code is sound, but its JSON schema is broken: `$defs.receiptBody` has
`additionalProperties: false` and lists neither `schema_version` nor `observation`. With a real JSON Schema
validator the old schema accepted all 76 real receipts and the new one accepts none (and rejects a new-format
receipt). The manifest installs this file into consumer repositories and T-027 reads it. Nothing in the suite
validated a receipt against the schema, which is why verification passed. Fix the schema, then add tests that
would have caught it. Change no receipt behaviour.

1. **Schema fix** (`schemas/execution-receipt.schema.json`):
   - declare `schema_version` (`enum [1, 2]`) and `observation` (a `$ref` to the observation definition) in
     `receiptBody.properties`, so a v1 receipt and a v2 receipt are both valid;
   - the v1 branch must **forbid** an `observation` key; the v2 branch must **require** it;
   - text values: make the schema agree with the code. The code accepts any non-empty string; the schema's
     `nonempty` pattern rejects leading/trailing whitespace. Align the **schema to the code** (a non-empty
     string); do not change `scripts/execution_receipt.py`.
2. **Agreement test with no third-party library** (`tests/test-execution-receipt.py`): read the schema as JSON and
   assert `set(receiptBody.properties) == set(execution_receipt.FIELDS)`, `receiptBody.required` equals the v1
   field list `FIELDS_V1`, and the observation and usage property sets equal `OBSERVATION_FIELDS` and `USAGE_FIELDS`.
   Mutating the schema or the code lists must make the test fail.
3. **Missing negative tests** (all must fail against today's code if they were wrong): `{"source":"guessed","value":"x"}`
   is rejected (this test must use a non-null value so that only the source check can reject it); a v1 receipt
   that carries an `observation` block is rejected; `true` as a usage count is rejected; the number `7` as the model is
   rejected; a v2 receipt without `observation` is rejected.
4. The real-validator command in the verification list validates every UUID-named receipt in
   `$PURRFECT_LIVE_ROOT/.tasks/receipts` against the schema when `jsonschema` is importable, and prints `SKIP`
   otherwise. `jsonschema` may not be installed here; the Architect re-checks with a real validator.
