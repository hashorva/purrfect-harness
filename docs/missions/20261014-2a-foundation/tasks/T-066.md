## Objective

Implement `scripts/drive-cli.sh` to drive a CLI inside an isolated `tmux` session using `scripts/drive_cli_rules.py`, and test it against a fake shell-script CLI inside a real `tmux` session.

1. `scripts/drive-cli.sh`:
   - Usage: `scripts/drive-cli.sh <workspace> -- <cli argv...>`. Validate `<workspace>` is an existing directory, `--` separator is present, and `<cli argv...>` is non-empty (exit `2` on invalid usage or missing `tmux`).
   - Resolve `<workspace>` with `pwd -P` so `drive_cli_rules.py` checks the canonical workspace path.
   - Create a local transcript directory under `${DRIVE_CLI_OUT_ROOT:-.tasks/drive}/<UTC time>/` (e.g. `YYYYMMDDTHHMMSSZ-$$`) and write `command.json`, `pane.log`, `events.jsonl`, and `result.json` (`exit_code`, `reason`, `rule_id`). Ensure `.gitignore` ignores `.tasks/` (only touch `.gitignore` if `.tasks/` is not already ignored).
   - Start `<cli argv...>` in `<workspace>` inside an isolated tmux server (`tmux -L "drive-cli-$$-..." -f /dev/null new-session -d ...` with `remain-on-exit on`) and always clean up the tmux server in an `EXIT` trap.
   - Poll `tmux capture-pane -p`:
     - Track only the unanswered suffix of the pane text (after any prompt already answered) so an answered folder-trust prompt in scrollback is never re-evaluated.
     - On pane change, reset the stall timer and pass the active pane text to `scripts/drive_cli_rules.py --workspace "$WORKSPACE"`.
     - `decision == "answer"`: send the rule's answer (`y` + `Enter`) via `tmux send-keys`, record the event in `events.jsonl`, and advance the answered-line offset.
     - `decision == "stop"` (`never` or `unknown_prompt`): kill the tmux session, print the captured pane text to stdout/stderr, write `result.json`, and exit `3`.
     - If the pane text does not change for `${DRIVE_CLI_STALL_SECS:-90}` seconds (validate positive number, default `90`): kill the tmux session, print the pane text, write `result.json`, and exit `4`.
     - When the pane process exits (`#{pane_dead}` is `1`) and no unanswered stop/refusal prompt is on screen: write final `pane.log` and `result.json` and exit with `#{pane_dead_status}`.
2. `tests/test-drive-cli.sh` and `tests/run-tests.sh`:
   - Always run a pure-Python `drive_cli_rules.match_pane` sanity check first.
   - If `! command -v tmux >/dev/null 2>&1`, print `SKIP: tmux not installed; skipping tmux integration tests` and exit `0`.
   - Using a FAKE CLI shell script in a temp dir (never a real provider CLI) and an isolated `DRIVE_CLI_OUT_ROOT` in the temp dir, test:
     - ALLOWED exact-workspace folder-trust prompt is answered `y`, fake CLI finishes exit `0`, transcript files exist under `<out-root>/<UTC time>/`.
     - Folder-trust prompt for a different path stops the session, prints pane text, and exits `3`.
     - Every NEVER category (`write_outside_workspace`, `delete_ignored_files`, `push_network_install`, `git_history_changes`, `credits_payment`) stops the session, prints pane text, and exits `3` without sending `y`.
     - Unknown prompt stops the session, prints pane text, and exits `3`.
     - Stall with no pane change (`DRIVE_CLI_STALL_SECS=1`) stops the session, prints pane text, and exits `4`.
   - Wire `tests/test-drive-cli-rules.py` and `tests/test-drive-cli.sh` into `tests/run-tests.sh`.
