## Objective

Owner Gate 0 decision 2: a live probe may change an active mission, but never silently.

1. `fleet_state.py resolve`: for a v2 fleet, call `resolve_v2` against the current
   `.tasks/fleet-inventory.json`; `--model/--effort/--speed` remain equality assertions against
   the resolved values. v1 fleets: exactly today's path.
2. Drift: compare the resolved `(provider, model, effort, speed)` with the last event for that
   seat in `.tasks/drift/<mission slug>.jsonl`, or, when there is none, with the binding the
   fleet's approval recorded (for v2, the resolution at freeze time; store it as
   `seats.<seat>.approved_resolution` when freezing). If different, append one JSON line
   `{"at", "mission", "seat", "from": {...}, "to": {...}, "inventory_sha256"}`, flush and fsync.
   If the append fails, print `ERROR: drift event could not be written` and exit non-zero.
3. Both launchers call this before the lock, so a failed drift write leaves no lock, spec, log
   or receipt. The spec records the resolved model (field `model`, as today).
4. Tests: a v2 fixture fleet and two inventories whose newest family model differs: two spawns
   give exactly one drift event; a third spawn with the same inventory adds none; a drift
   directory that cannot be written (`chmod 500`) makes the spawn exit non-zero with no run
   artifact; a v1 fleet never creates a drift file.

The invocation above is descriptive; the Front Desk picks an approved frozen
seat from this mission's `fleet.json`. Complete only this task and stay within
the allow-list below.
