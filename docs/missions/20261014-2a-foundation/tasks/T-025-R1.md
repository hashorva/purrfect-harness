## Objective

**Why this task exists (a safety fix).** Before T-025, a seat marked `source: fallback` had to carry one of the known `FALLBACKS` model names. T-025 deleted
that constant, and the check went with it: a forged seat with any model name now passes. The Architect reproduced it in a scratch clone: an inventory with one
seat set to `source: fallback` and the made-up model `gpt-forged-terra-99` is refused by the old tree (`validate-inventory` and the v1 `freeze`), and accepted by the new
tree, which writes a `fleet.json` containing that model. No code writes `fallback` any more, so such a seat is either old evidence or forged.

1. **The fix:** the v1 `freeze` must **refuse any seat whose inventory `source` is `fallback`** with a clear `ERROR:` message that names the seat and says fallback
   bindings are no longer allowed. Old inventories that carry a `fallback` seat must still be *readable* by `validate-inventory` (they are historical evidence); only
   `freeze` refuses. Do not change `freeze_v2` (it is not affected).
2. **Tests** (in `tests/test-fleet-state.py`), each asserting the exact `ERROR:` text and written to fail if the check is removed:
   - the forged-seat reproduction: an inventory whose seat has `source: fallback` and the model `gpt-forged-terra-99`: `freeze` exits non-zero, writes no `fleet.json`;
   - a `fallback` seat with a real-looking model is refused by `freeze` as well;
   - restore the tests that guarded the removed check, so the three mutations that survived T-025 are caught: dropping the fallback check on **health** (the
     `healthy-fallback` case must run against a seat that really has `source: fallback`, not an `unavailable` one), on **retained last-good state**, and on the
     **current-unavailable status**. Read the Architect's T-025 entry for the exact mutations;
   - `validate-inventory` still accepts an old inventory with a `degraded` `fallback` seat (pin this as the intended behaviour).
3. Prove once per group, in a **temporary copy** of `scripts/fleet_state.py` (never in the live tree), that each new test fails when its check is removed, and record
   one line in the PROGRESS entry. Do not weaken or remove any existing test. Change no behaviour of valid fleets or of a probe failure (an unavailable seat stays unavailable).
