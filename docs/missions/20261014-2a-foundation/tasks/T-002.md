## Objective

Make `harness-registry.json` the only source of `PROVIDERS`, `CAPABILITIES`,
`SEAT_SPECS` and the Cursor executable name in `scripts/fleet_state.py`.
`FALLBACKS` stays a literal in `fleet_state.py` (F004 deletes it).

Design (decided by the Architect; do not change it):

- **Persisted names do not change in this task.** The frozen
  `docs/missions/20261014-2a-foundation/fleet.json` (read-only), the inventory v1
  file and ExecutionSpec v3 all record the Cursor provider as `agent`. They must
  keep validating byte for byte. So `fleet_state.py` uses a *legacy view* of the
  registry: each provider is named by its legacy name if it has one (`cursor` →
  `agent`), otherwise by its key. F004 (fleet v2) moves persisted data to
  canonical names.
- In `scripts/harness_registry.py` add:
  - validation: `legacy_names` has at most one entry, each non-empty text, and no
    legacy name equals any provider key;
  - `legacy_view(registry)`: returns `providers` (tuple, registry order),
    `capabilities` (dict), `seat_specs` (dict of 2-tuples) and `executables`
    (persisted name → registry `binary`), all keyed by the persisted name;
  - `canonical_provider(registry, name)`: maps a key or legacy name to the key;
    raises `RegistryError` on an unknown name.
- In `scripts/fleet_state.py`, replace the literal definitions of `PROVIDERS`,
  `CAPABILITIES`, `SEAT_SPECS` and `EXECUTABLES` with values loaded once from
  `legacy_view(load_registry())`. The names stay (dispatch_policy.py imports
  `CAPABILITIES`). A missing or invalid registry must fail closed: every CLI
  command exits non-zero with an `ERROR:` line that names the registry. Do not
  fall back to built-in values.
- The import of `harness_registry` must work in all three ways `fleet_state.py`
  is loaded: run as a script, imported by `scripts/dispatch_policy.py`, and loaded
  with `importlib.util.spec_from_file_location` from a test.
- `tests/test-registry.py`: the parity test now compares against a **golden
  literal copy** of the four old constants as they were at commit `1345c67`
  (copy them into the test with a comment naming that commit). Assert that the
  registry legacy view equals the golden values, that `fleet_state.PROVIDERS`,
  `CAPABILITIES` and `SEAT_SPECS` equal them too, and that registry `fallbacks`
  equals `fleet_state.FALLBACKS`. Comparing the registry to values derived from
  the registry would prove nothing. Add negative tests for: invalid
  `billing_class`, non-boolean `no_zdr`, boolean or text `priority`, two legacy
  names, a legacy name equal to a provider key, and `canonical_provider` on an
  unknown name.
- Add a real-entry negative test: with `harness-registry.json` absent from a
  temporary copy of the repo, `python3 scripts/fleet_state.py validate-fleet <fleet>`
  exits non-zero and prints the registry error.
- Fixtures that copy `scripts/` into a temporary repo must now also copy what
  `fleet_state.py` loads: add `harness_registry.py` to the copy list in
  `tests/test-execution-integration.py` and copy `harness-registry.json` to the
  fixture root; copy `harness-registry.json` into the temporary root in
  `tests/test-verification-record.py` (lines 286-294). Change nothing else in
  those two files.
- Add `tests/test-registry.py` to `tests/run-tests.sh` as one `check` line next
  to the fleet-state check. It is not in the suite today.

Do not touch `harness-registry.json`: the parity proof requires the data to stay
as it is. Do not touch `scripts/execution_spec.py`: its `PROVIDERS` is the frozen
v1-v3 evidence schema, and old evidence must not depend on mutable registry data.
