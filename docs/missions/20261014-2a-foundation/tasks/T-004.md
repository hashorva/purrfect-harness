## Objective

Mission-init and dispatch need one check that the four CLIs are the right
programs and are logged in, instead of ad-hoc `which -a` checks. On this Mac,
`agent` resolves to two different programs (Grok Build and Cursor). That is why
the Cursor binary is `cursor-agent`, and why the doctor checks registry
`binary` names only, never legacy names.

1. Registry data. Add two required fields to every provider in
   `harness-registry.json`, and validate them in `scripts/harness_registry.py`:
   - `identity_pattern`: a regex that the first line of `identity_check` output
     must fully match. Use these values. The Architect recorded the outputs on
     this Mac on 2026-10-14:

     | provider | recorded `--version` output | `identity_pattern` |
     | --- | --- | --- |
     | claude | `2.1.299 (Claude Code)` | `^\d+\.\d+\.\d+ \(Claude Code\)$` |
     | codex | `codex-cli 0.162.0` | `^codex-cli \d+\.\d+\.\d+$` |
     | cursor | `2026.10.14-0f9edde` | `^\d{4}\.\d{2}\.\d{2}-[0-9a-f]{7,}$` |
     | agy | `1.3.5` | `^\d+\.\d+\.\d+$` |

     Grok's `agent --version` prints `grok 1.0.52 (0920c8169e27) [stable]`.
   - `login_check`: a non-billable command that exits non-zero when logged out:
     claude `["claude","auth","status"]`, codex `["codex","login","status"]`,
     cursor `["cursor-agent","status"]`, agy `["agy","models"]` (agy has no
     status command; listing models needs a login and makes no model call).
   The validator rejects a pattern that does not compile and an empty
   `login_check`. The existing one-negative-test-per-field loop covers absence.
2. `scripts/fleet_doctor.py` (logic) and `scripts/fleet-doctor.sh` (a thin
   wrapper that runs it with `PYTHONDONTWRITEBYTECODE=1` and passes its exit
   code). For each provider in the registry, using its `binary`:
   - Collect every PATH hit in PATH order and resolve each with `realpath`.
   - No hit: `WARN` (not installed); skip the other checks for it.
   - Two or more hits that resolve to **different** real files: `ERROR`.
   - Two or more hits that resolve to the **same** real file (a repeated PATH
     entry, or a symlink to the same binary): `WARN`. A single symlink hit is fine.
   - Run `identity_check` with argv[0] replaced by the first hit's path. If the
     first output line does not fully match `identity_pattern`: `ERROR`.
   - Run `login_check` the same way. Non-zero exit: `ERROR` (logged out).
     A timeout (30 s) is `WARN`, not `ERROR`. **Never print the output of the
     login check**: `cursor-agent status` prints the account email.
   - Print one line per finding: `OK|WARN|ERROR <provider>: <message>`. Exit 1
     if any `ERROR`, else 0. `ERROR` is only for the three cases above.
3. `tests/test-fleet-doctor.py`. Use fake executables in temporary directories
   and run `scripts/fleet-doctor.sh` with `PATH` set to those directories plus
   `/usr/bin:/bin`. Never call the real CLIs. Cases:
   - all four healthy: exit 0, no `ERROR`;
   - two different `codex` files in two PATH directories: exit non-zero, `ERROR`;
   - a wrong `--version` output (Grok's line for `cursor-agent`): `ERROR`;
   - a login check that exits 1: `ERROR`;
   - the same directory twice in PATH: `WARN`, exit 0;
   - a symlink to the same binary in a second directory: `WARN`, exit 0;
   - a login check that prints a marker string: the marker never appears in the
     doctor output;
   - each `identity_pattern` matches its own recorded output above and none of
     the other four outputs (including Grok's).
4. Add `tests/test-fleet-doctor.py` to `tests/run-tests.sh` as one `check` line.
   The real-machine doctor run stays out of the suite and CI; it is a
   verification command of this task only.
5. Add `scripts/fleet-doctor.sh` and `scripts/fleet_doctor.py` to the same
   `harness-manifest.json` ownership lists that hold `scripts/harness_registry.py`.
