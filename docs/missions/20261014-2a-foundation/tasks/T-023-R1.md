## Objective

**Why this task exists.** The Architect's review of T-023 passed the resolver code, but 4 of 19 mutations survived: the code handles each case
correctly today (or, for S1, wrongly in one situation) and no test would catch a regression. Fix S1 and add tests for S2 and S3.

1. **S1 (one-line code fix):** the resolver reads the *fast* setting from the mission policy instead of from the seat. With fast enabled for the mission, a seat
   set to standard speed resolved to `grok-4.8-high`, which is not in the inventory (only `grok-4.8-high-fast` is). The resolver must use the **seat's** speed
   (a seat with speed `standard` never gets a `-fast` model, whatever the mission policy says). Add a test at `resolve_v2` / the `resolve-v2` CLI that
   fails without the fix: mission policy `fast: true`, seat speed `standard`, an inventory with both `grok-4.8-high` and `grok-4.8-high-fast`: the result is `grok-4.8-high`, and with an inventory that has only the `-fast` model the result is `unavailable` (exit 1), not a guessed id.
2. **S2:** a test that the resolver moves on to the next door when the first healthy door has no model of the seat's family (door 1 healthy, no model of the family; door 2 has it: door 2 is chosen).
3. **S3:** the refusals for a fast seat under `policy.fast: false` and for a family that matches no door are tested through the resolver itself (`resolve-v2` CLI), asserting the exact `ERROR:` text, not only through `validate-fleet`.
4. **S4 (optional):** a test that an encoding error is refused, not skipped. This path is probably unreachable with the real registry; skip it if it needs the registry to be modified.
5. Each new test must fail when its check is removed: prove it once per group in a **temporary copy** of `scripts/fleet_state.py` (never in the live tree) and record one line in the PROGRESS entry. Do not weaken or remove any existing test.
