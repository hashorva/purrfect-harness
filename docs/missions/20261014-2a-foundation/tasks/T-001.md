## Objective

Add the registry as data, with a loader and a parity test. Do not change any
existing script yet.

Why this slice is small and safe: the four constants in `fleet_state.py` are
the source of truth today. A parity test proves the new data matches them
before a later task removes them. If you edit `fleet_state.py` now, the proof
is lost.

1. Create `harness-registry.json`. It holds providers, doors and pools.
   - Provider names: `claude`, `codex`, `cursor`, `agy`. The provider `cursor`
     has binary `cursor-agent` and the legacy name `agent`. Do not add `grok`
     here; feature F002 does that.
   - Per provider: probe command, list parser, identity check (`--version`),
     effort and fast encoding, discovery directory, capabilities.
   - Per door: billing class (`included`, `credits` or `api`), pool, `no_zdr`
     flag, priority.
   - Also hold the seat specs and fallbacks, with the same values as the
     constants.
2. Create `scripts/harness_registry.py`. It loads and validates the file. It
   fails with a clear message on a missing field.
3. Create `tests/test-registry.py`. It checks:
   - the registry equals the old constants (map `cursor` to `agent`);
   - each missing required field fails validation (one negative case per field);
   - `agent` is only a legacy name, never a provider key.
4. Add `harness-registry.json` and `scripts/harness_registry.py` to the
   ownership lists in `harness-manifest.json`.
