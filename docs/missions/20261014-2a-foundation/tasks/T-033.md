## Objective

1. `schemas/task-plan.schema.json`: `{plan_id, mission, verdict: READY|BLOCKED, blocking_question
   (required when BLOCKED), tasks: [{id, feature, title, category, size: S|M|L, review:
   Architect|code-reviewer, seats_to_avoid: [..], depends_on: [..], allow_list: [..] (minItems 1),
   verification: [[argv strings, minItems 1]] (minItems 1), steps: [text] (minItems 1)}] (minItems 1)}`.
2. `schemas/review-verdict.schema.json`: `{run_ids: [..], commits: [{commit, verdict: PASS|FAIL,
   evidence: [text] (minItems 1)}] (minItems 1), findings: [{id, severity: blocking|non-blocking,
   text}], verdict: PASS|FAIL}`.
3. `scripts/validate_verdict.py <schema> <json-file>` implements the draft 2020-12 subset these
   schemas use (`type`, `required`, `properties`, `additionalProperties: false`, `items`,
   `enum`, `minItems`, `minLength`, `pattern`, `if`/`then` only if you use it) and refuses a
   schema that uses any other keyword. `--check-schema <schema>` validates the schema itself
   against that subset. Exit 0 valid, 1 invalid (`ERROR: verdict: <json path>: <reason>`), 2 usage.
4. Fixtures `tests/fixtures/verdicts/`: one good file per schema; bad files with a missing field,
   a wrong type and empty `steps` (plan) / empty `evidence` (review).
5. New `tests/test-verdict.py`, wired into `tests/run-tests.sh`; add the script and both schemas
   to the manifest ownership lists.
