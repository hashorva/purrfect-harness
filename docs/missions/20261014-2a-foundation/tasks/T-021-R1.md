## Objective

**Why this task exists.** The Architect's review of T-021 found that `encode_model` accepts a model name that
already carries an effort token or a fast suffix. For example `grok-4.7-xhigh` with effort `medium` becomes
`grok-4.7-xhigh-medium`: the adapter accepts it and `cursor-agent` would reject it at run time. T-023 takes model
names from the inventory, and those names are already encoded, so T-023 would hit this. Eight mutations of
T-021's code also survived because of missing negative tests. Fix the code at the source and add the tests.

1. `encode_model(registry, provider, base, family, effort, fast)` must **refuse a `base` in which `decode_model`
   finds an effort token or a fast suffix** (raise `RegistryError` with a clear message that names the base and
   says it is already encoded). A plain base such as `grok-4.7`, `composer-2.5`, `gemini-3.8-flash` still encodes as before.
2. Add tests in `tests/test-registry.py` that kill the surviving mutations. Each test must fail when its mutation
   is applied in a **temporary copy** (never in the live tree); prove this once per test group and record it in one line of the PROGRESS entry:
   - already-encoded bases are refused: `grok-4.7-xhigh` (with effort `medium`), `gemini-3.8-flash-high`, `composer-2.5-fast`;
   - H: for the flag providers (`claude`, `codex`) the effort is **not** put in the model name; `claude-opus-5-5-high` as a base is refused, and a plain base comes back unchanged;
   - I: `fast` requested for `agy`, `claude` or `codex` is refused;
   - M: an effort outside the provider's tokens is refused (for example `gemini-3.8-flash` with `xhigh`);
   - K: the effort-token whitelist is enforced by the registry validator (an unknown token in the registry is rejected);
   - J: the `fast_suffix` / `fast_encoding` agreement check is enforced (a provider with `fast_encoding` `model-name` and no `fast_suffix`, or the reverse, is rejected);
   - L: a door without a `provider` key raises `RegistryError`, not `KeyError`;
   - O: the five door-to-provider values are pinned by literal: `claude`→`claude`, `codex`→`codex`, `cursor-composer`→`cursor`, `cursor-grok`→`cursor`, `agy`→`agy`;
   - P: `decode_model` with an empty base is refused.
3. Change nothing else: not `harness-registry.json`, not any other script.
