## Objective

Written from the Architect's T-029 review (verdict FAIL on one blocking issue and 10 uncaught mutations).

1. **Code (`scripts/execution_runner.py`, ledger step only):** catch any `Exception` around the whole ledger step (build row, validate, write). On failure print
   `WARN: ledger row not written: <stage or field>` (never the refused value), and leave the exit code, the `receipt=` line and the receipt bytes exactly as without the ledger.
   Do not change any other runner behaviour.
2. **Tests (`tests/test-execution-integration.py`, built in temporary repositories with fake provider CLIs on PATH; never launch a real provider):**
   a. read-only `.tasks/ledger` directory: exit code and receipt equal the provider's, WARN present;
   b. a validator refusal (a hostile pool or label value): same, and the hostile value appears in neither stdout, stderr nor the log;
   c. a registry the worker left malformed (a JSON list): same exit code and receipt as the provider's, WARN present, no traceback;
   d. a write failure (unwritable path): same;
   e. rows exist for a `timed_out` run and a `launch_failed` run (extend the existing failed-run test);
   f. a second write with the same run id does not replace the first row (compare bytes);
   g. the row's observed model comes from the receipt's `observation`, never from the spec (use a spec model different from the observed one);
   h. the row's changed-file count equals the receipt's;
   i. input and output token counts are not swapped (use distinct values);
   j. the per-check label keeps its index (`bash#1`, `bash#2`).
   Each of a-j must fail when the corresponding fault is injected: prove each in a **temporary copy** of the runner (never the live tree) and record one line per test in the PROGRESS entry.
3. Do not weaken any existing test. Commit as `fix(runner): a ledger problem never changes a run's outcome; tests for the ten faults`.
