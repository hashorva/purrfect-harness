## Objective

A ledger row today says `"door": "economy"` (the tier, not the door), marks the launcher's own
model and effort as `observed` (the CLI never reported them), and picks the Cursor door by
speed, so Grok at standard speed is counted as Composer. Fix all three in one schema step.

1. **Schema version 2.** `scripts/ledger.py` `SCHEMA_VERSION = 2`; the JSON schema title says
   `LedgerRow v2` and `schema_version` is `{ "const": 2 }`. The error for any other value is
   `schema_version: must be 2`.
2. **`configured` source, only on three fields.** `requested_model`, `resolved_model` and `effort`
   accept the sources `observed, configured, estimated, unknown` (in that order in the error
   message: `<field>.source: must be one of observed, configured, estimated, unknown`). Every other
   flag field keeps exactly `observed, estimated, unknown`; `configured` there is refused with
   `<field>.source: must be one of observed, estimated, unknown`. `configured` follows the same
   null rule as `observed` (`<field>.value: must not be null when source is configured`).
   In the schema add a `$defs/configuredTextFlag` (same shape as `textFlag`, source enum
   `["observed", "configured", "estimated", "unknown"]`) and point only those three properties at it.
   Update the module docstring: `configured` = taken from the run's frozen configuration;
   `observed` = only what the CLI itself reported.
3. **New required field `tier`**, placed right after `door` in `FIELDS` and in the schema
   `required` list. Allowed values: `"economy"`, `"premium"`, or `null` (brain runs have no tier).
   Anything else (including `""`, other case, numbers, booleans, lists) is refused with exactly
   `tier: must be one of economy, premium or null`. Schema: `"tier": { "enum": ["economy", "premium", null] }`.
4. **Row builder** (`scripts/execution_runner.py`, `build_ledger_row`):
   - `schema_version` 2; `tier` = the `tier` argument when it is `economy` or `premium`, else `null`.
   - `requested_model` and `effort` come from `receipt["requested_configuration"]` (`model`, `effort`);
     `resolved_model` from `receipt["resolved_configuration"]["model"]`; all with source `configured`.
     A missing, empty or literal `"unknown"` value becomes `{"value": null, "source": "unknown"}`.
     Never copy them from `spec["model"]` / `spec["effort"]`.
   - `door` = the registry door name. For Cursor (`provider` `agent`/`cursor`) the door is
     `cursor-<family>`, where family is the resolved model id up to its first `-`
     (`grok-4.7-high` → `cursor-grok`, `composer-2.5` → `cursor-composer`). Speed plays no part.
     Other providers: the door is the CLI name (`claude`, `codex`, `agy`). When the name is not a
     key of `harness-registry.json` `doors`, door, pool and billing_class are all `"unknown"`.
     Replace `registry_pool_and_billing` with one function that returns `(door, pool, billing_class)`.
     Keep reading the registry exactly as today (working tree, `json.loads`, `"unknown"` on
     error); T-042 changes where it is read from.
5. **Fixtures:** all six files in `tests/fixtures/ledger/` move to v2: `schema_version` 2, `door`
   = the real door for the row's `cli` (`claude`, `agy`, ...), `tier` = the old `door` value. In the
   two `good-*` fixtures, the three configured fields that said `observed` now say `configured`.
   Keep each `bad-*` fixture failing with its current message. Keep the existing line layout.
6. **Tests** (`tests/test-ledger.py`; no new test file, so nothing new to wire into
   `tests/run-tests.sh`): update the contract tests for v2 and `tier` (the section-8 list stays
   literal; `tier` is an allowed extra next to `schema_version`). Add tests through the real CLI
   for item 2 (one subtest per field, both directions) and item 3 (every refused value above, plus
   `premium` and `null` accepted). Add a builder test class that calls `build_ledger_row` with an
   in-test spec and receipt (repo = the repository root) and validates the row, covering: Grok and
   Composer at both `standard` and `fast`; an unknown family; codex and claude doors; tier
   `None` and an invalid tier; requested ≠ resolved model; effort `"unknown"`. Assert the schema's
   `schema_version` const, the `tier` enum and both source enums literally.
   In `tests/test-execution-integration.py` change only the mutation in
   `test_ledger_row_observed_model_matches_receipt_not_spec`, which names a removed local
   variable: it must still replace the observed-model value with the spec's model (`spec["model"]`).
