## Objective

Create the fixed rule data file `scripts/drive-cli.rules.json` and pure-Python rule matcher `scripts/drive_cli_rules.py` so prompt classification and key-press decisions are deterministic and unit-testable without `tmux`.

1. `scripts/drive-cli.rules.json`: define a fixed JSON rule table (`"schema_version": 1`) with:
   - `"never_rules"`: ordered list of refusal rules (`"decision": "stop"`, `"exit_code": 3`) covering all 5 required NEVER categories:
     - `write_outside_workspace` (writing/editing/modifying/creating/deleting paths outside the workspace, `../`, `/etc/`, `~/`, external directories)
     - `delete_ignored_files` (`git clean -fdX`, `git clean -fdx`, deleting/removing ignored or untracked files)
     - `push_network_install` (`git push`, `curl`, `wget`, `npm/pnpm/yarn/pip/brew/cargo install`, network/fetch/deploy prompts)
     - `git_history_changes` (`git reset --hard`, `git rebase`, `git commit --amend`, `git push --force`, `git filter-branch`, history rewrites)
     - `credits_payment` (credits, billing, payment, purchase, charge, upgrade plan, spend limit prompts)
   - `"allowed_rules"`: single rule `folder_trust` (`"decision": "answer"`, `"answer": "y\n"`) matching folder-trust prompts ONLY when the prompt explicitly names the run's exact workspace path.
   - `"prompt_patterns"`: regex patterns that identify interactive prompts (`[y/n]`, `(y/n)`, `yes/no`, `do you trust`, `allow`, `approve`, `confirm`, `press enter`, numbered selection prompts).
2. `scripts/drive_cli_rules.py`: implement:
   - `RulesError(ValueError)` and `load_rules(path=DEFAULT_RULES_PATH)` validating `schema_version == 1`, all 5 required `never_rules` IDs, `allowed_rules` (`folder_trust`), and compiling regexes.
   - `match_pane(pane_text: str, workspace: str, rules: dict | None = None) -> dict`:
     - Require `workspace` to be a non-empty absolute path without `..` segments (raise `RulesError` otherwise).
     - Evaluate `never_rules` FIRST across the active pane text; any match returns `{"decision": "stop", "category": "never", "rule_id": <id>, "answer": None, "exit_code": 3}`.
     - Evaluate `allowed_rules` (`folder_trust`): match only when a folder-trust prompt names `workspace` on an exact path token boundary (not a parent, child, sibling like `<workspace>-other` or `<workspace>/sub`, or `..` traversal) and no other unapproved prompt line is present; return `{"decision": "answer", "category": "allowed", "rule_id": "folder_trust", "answer": "y\n", "exit_code": None}`.
     - If any `prompt_patterns` (or a folder-trust prompt for any other path or missing path) matches, return `{"decision": "stop", "category": "unknown_prompt", "rule_id": None, "answer": None, "exit_code": 3}`.
     - Otherwise return `{"decision": "wait", "category": "no_prompt", "rule_id": None, "answer": None, "exit_code": None}`.
   - CLI entrypoint (`python3 scripts/drive_cli_rules.py --workspace <path> [--rules <path>]`) reading pane text from stdin and printing the JSON decision.
3. `tests/test-drive-cli-rules.py`: unit-test `load_rules` schema guards, exact workspace folder-trust acceptance, rejection of sibling/child/parent/missing/`..` paths as `unknown_prompt` (`exit_code == 3`), every single `never_rules` category (`exit_code == 3`), compound prompts where a `never` pattern appears alongside a valid workspace trust prompt (`never` wins), unknown prompts (`exit_code == 3`), and ordinary non-prompt output (`decision == "wait"`).
4. Commit as `feat(autopilot): add fixed drive-cli rule table and pure-python matcher (T-065)`.
