## Objective

**Why this task exists.** The Architect's review of T-022 found that the v2 validation behaves correctly and v1 fleets are
unchanged, but 16 of 22 mutations survived: the tests are too weak. One required test is missing, the negatives only check
for a non-zero exit (a guard can disappear and the code crashes later), and two malformed inputs make the code crash with a
traceback instead of a clean refusal. This task fixes that. Change no behaviour of valid v1 or v2 fleets.

1. **(a) Effort negative:** the test named `bad-effort` changes the speed, not the effort. Add a real effort negative
   (for example codex with effort `max`, agy with effort `xhigh`: efforts a door's provider cannot run) so that deleting the effort check fails a test.
2. **(b) Specific errors:** every negative test must assert its own `ERROR:` message text (at the CLI entry point), not only a
   non-zero exit code.
3. **(c) More negatives**, each asserting its message: `no_zdr` problems, an empty or duplicated `billing_classes` list, duplicated
   `doors`, extra keys in `policy` or in a seat, empty `seats`, `schema_version` 3, missing, or the string `"2"`, and an approval
   status `draft` in a v2 document.
4. **(d) Clean errors, not tracebacks:** a document that is not a JSON object must give `ERROR: fleet must be an object`
   (call `obj(doc, "fleet")` before `doc.get`), and items in `billing_classes` / `doors` that are not text must give a clean `PolicyError` (type check before
   `set()`), each with a negative test at the CLI.
5. **(e) Designed refusal:** until the v2 resolver exists (T-023), `resolve` refuses a document with `schema_version` 2 with the
   explicit error `fleet v2 is not resolvable yet`, with a negative test. The launchers then stop on a designed check, not on a `KeyError: 'provider'`.
6. **(f) Optional:** an agreement test between `schemas/mission-fleet.schema.json` and the v2 code shape, gated on `jsonschema` being importable
   (skip with a printed notice otherwise), in the style of the receipt schema test.
7. Each new test must fail when its check is removed: prove it once per group in a **temporary copy** of `scripts/fleet_state.py`
   (never in the live tree) and record one line in the PROGRESS entry. Do not weaken or remove any existing test.
