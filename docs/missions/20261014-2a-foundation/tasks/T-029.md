## Objective

1. After `write_receipt`, the runner builds a row from the spec, the receipt (outcome, exit code,
   timestamps → wall time, changed paths → `diff_size.files`, scope result) and its
   observation; fields it cannot know are `unknown` / empty lists / null text. It validates the
   row with `ledger.py`'s function and writes `.tasks/ledger/<run_id>.json` atomically
   (no-clobber). This happens for every outcome, including `failed`, `timed_out` and `launch_failed`.
2. A row that fails validation or cannot be written prints `WARN: ledger row not written: <reason>`
   to the log; the receipt, outcome and exit code are unchanged. (The receipt is the primary
   evidence; the ledger is a summary.)
3. Tests (integration, temporary repo): completed and failed fake runs each produce one valid
   row; `git status --porcelain` stays empty after the row is written; `git check-ignore -q
   .tasks/logs/<run_id>.log` succeeds and `git add -A --dry-run` lists no `.tasks/` path.
