## Objective

1. Required door field `provider` (a provider key). Values: `claude`→`claude`, `codex`→`codex`,
   `cursor-composer` and `cursor-grok`→`cursor`, `agy`→`agy`.
2. Required provider field `model_name_encoding`: `null` for providers with `effort_encoding`
   `flag`; for `model-name` providers:
   `{"effort_tokens": [...], "fast_suffix": "-fast"|null, "families_without_effort": [...]}`.
   Cursor: effort tokens `none, minimal, low, medium, high, xhigh, max`, fast suffix `-fast`,
   families without effort `["composer"]`. agy: tokens `low, medium, high`, fast suffix `null`.
3. Functions `encode_model(registry, provider, base, family, effort, fast)` and
   `decode_model(registry, provider, model) -> {"base", "effort"|None, "fast": bool}`.
   Encoding never adds `-fast` unless `fast` is true.
4. CLI `python3 scripts/harness_registry.py encodings`: prints one line per provider:
   `<provider> effort=<flag|model-name|unsupported> fast=<...> tokens=<comma list or ->`.
5. Tests: validation of both fields; encode/decode round trips for `grok-4.7` (medium,
   standard → `grok-4.7-medium`; xhigh, fast → `grok-4.7-xhigh-fast`), `composer-2.5` (any
   effort → `composer-2.5`), `gemini-3.8-flash` high → `gemini-3.8-flash-high`; the adapter
   (the current provider contract; today 6) accepts every model `encode_model` produces with matching spec effort/speed;
   `legacy_view` unchanged.
