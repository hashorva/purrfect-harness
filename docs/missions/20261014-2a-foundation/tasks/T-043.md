## Objective

Owner rule: a skipped check is a failure. Today `verify` looks only at the exit code, so a check
that skips its real work and exits 0 (unittest `OK (skipped=1)`, the jsonschema-gated block in
`tests/test-fleet-v2.py` that prints `SKIP ...`) produces a `pass` record.

1. **Patterns** (`scripts/verification_record.py`, next to `RECORD_FIELDS`). Add
   `COMMAND_FIELDS` (the six existing command keys) and `SKIP_PATTERNS`, a tuple of
   `(name, reason, compiled bytes regex)` in exactly this order, all `re.M`:
   - `unittest`, "unittest summary reports skipped tests": `^OK \(skipped=[1-9][0-9]*`
   - `pytest`, "pytest summary reports skipped tests": `^=+ [^\n]*\b[1-9][0-9]* skipped\b[^\n]* =+[ \t\r]*$`
   - `tap`, "TAP line carries a skip directive": `^(?:not )?ok\b[^\n#]*#[ \t]*skip\b` (also `re.I`)
   - `marker`, "output line starts with SKIP": `^SKIP(?:PED)?\b` (case-sensitive)
   Add `SKIP_REASONS = {name: reason ...}` and `skip_kind(data)` (first matching name, or `None`).
   Above the tuple, a comment says why: each pattern is a runner's own summary or marker anchored
   at column 0, so prose like `identical-skipped=3`, "skips other missions" or JSON `"skipped"`
   never matches.
2. **verify.** After each command, `skipped = skip_kind(stdout) or skip_kind(stderr)`. When set:
   add `"skip_detected": <name>` to that command's outcome, print to stderr
   `VERIFY SKIP: command <1-based index> <json.dumps(argv)[:200]> reported skipped checks (<reason>)`,
   and the record's result is `fail`. Never print or store any captured output. The exit code is
   recorded unchanged.
3. **validate_record.** A command's keys are `COMMAND_FIELDS`, optionally plus `skip_detected`,
   which must be a string in `SKIP_REASONS` (a list or other non-string must raise
   `VerificationError`, not `TypeError`). Records without the key (every existing record) stay valid.
4. **revalidate_record.** A command is ok only when `exit_code == 0` and it has no `skip_detected`.
5. **Schema.** In `commands.items.properties` add
   `"skip_detected": {"type": "string", "enum": ["unittest", "pytest", "tap", "marker"]}` (not required).
6. **Tests** (`tests/test-verification-record.py`, through `scripts/verify-mission.sh`):
   - one entry-point case per pattern (a real unittest `skipTest`; a pytest summary line; a TAP
     `# SKIP`; `SKIP ...` on stdout; `SKIPPED [1] ...` on stderr): exit non-zero, result `fail`,
     `exit_code` 0, the expected `skip_detected`, `VERIFY SKIP: command 1 ` and the reason on stderr,
     and a canary printed by the check appears in neither the output nor the record (build the canary
     at run time, for example `'CANARY-a'+'b'`, so the argv does not contain it);
   - near misses, each printed on stdout and stderr, still `pass` with no `skip_detected`:
     `  installed=1  identical-skipped=3  conflicts=0`, `  ok   : fold skips other missions`, `OK`,
     `OK (expected failures=1)`, `OK (skipped=0)`, `test_fold_skips_other_missions ... ok`,
     ` SKIP indented`, `SKIPS`, `skip: lower case`, `===== 3 passed in 0.12s =====`,
     `ok 1 - skip handling works`, `{"skipped": {"brain": "not launched"}}`;
   - add label `skip` (`commands[0].skip_detected = "marker"` on the accepted pass record) to the
     revalidation test's labels;
   - add to the validator test's weakest list: undeclared command property, `skip_detected` of
     `"other"`, `""` and `["marker"]`; assert the schema enum equals `list(SKIP_REASONS)`; assert a
     record with `skip_detected: "unittest"` validates.

Out of scope, do not change: `tests/run-tests.sh` (its `check()` discards child output, see the
review note), `tests/test-fleet-v2.py`, the record `schema_version`.
