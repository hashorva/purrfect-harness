## Objective

**Why this task exists.** The Architect's review of T-024 passed the behaviour (v1 launcher output unchanged in 54 cases, one drift event per change,
a failed drift write stops the spawn before any lock/spec/log/receipt) but found two blocking gaps.

1. **Schema (a gap in how T-024 was written, not a worker fault):** `schemas/mission-fleet.schema.json` does not allow the new `approved_resolution`
   field that the v2 code now requires and writes, so with `jsonschema` installed `tests/test-fleet-v2.py` fails (it passes on the commit before T-024).
   Add `approved_resolution` (and every other key the v2 code now writes) to the v2 part of the schema with the right shape. Do not change v1.
2. **Agreement test with no third-party library** (in `tests/test-fleet-v2.py`): the verifier's Python may not have `jsonschema`, and a `jsonschema`-gated
   check was silently skipped and hid this regression. Add a dependency-free test that reads the schema as JSON and asserts that every key a v2 fleet document
   written by the code contains (build one with the real code path used by the tests) is declared in the v2 schema's properties, and that every key the schema
   requires is produced by the code. Mutating the schema (removing `approved_resolution`) must make this test fail.
3. **Two untested safety refusals** (the Architect removed each in a test copy and every T-024 test still passed): (a) on a v2 fleet the `--model`, `--effort`
   and `--speed` flags remain **equality assertions** against the resolved seat: a mismatching flag is refused before any lock, spec, log, receipt or provider call;
   (b) a v2 seat whose family has no available model is refused ("unavailable"), never guessed. Add a test for each in `tests/test-execution-integration.py`
   (real launcher in a temporary repository, fake providers first on PATH) asserting the exact refusal text and that nothing was created.
4. Each new test must fail when its check is removed: prove it once per group in a **temporary copy** (never in the live tree) and record one line in the
   PROGRESS entry. Do not weaken or remove any existing test. Change no behaviour of valid v1 or v2 fleets.
