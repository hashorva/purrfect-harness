## Objective

During a run the working tree belongs to the worker. Today the runner reads `harness-registry.json`
from the working tree *after* the provider exits, so a worker can choose its own row's pool and
billing class, or suppress the row by breaking the file. Read the registry as committed at the
run's `spec["base_commit"]` instead. Also make the validator refuse a `door` that is not a registry
door (review N1 of T-041: today `door: "economy"` validates).

1. **Runner: base-commit read** (`scripts/execution_runner.py`). Add
   `base_registry_doors(repo, base_commit)`. It returns the `doors` object of
   `git --no-replace-objects -C <repo> cat-file blob <base_commit>:harness-registry.json`
   (argv list, `stdin=subprocess.DEVNULL`, `capture_output=True`, `timeout=30`, `check=False`).
   It returns `{}` on any failure: `base_commit` not a non-empty string or starting with `-`;
   `OSError`/`subprocess.SubprocessError` from the call; non-zero exit; JSON or UTF-8 errors; a top
   level that is not an object; `doors` missing or not an object. Use `cat-file blob`, not
   `git show`, because plumbing never runs textconv. Use `--no-replace-objects`, because a worker
   can add `refs/replace/` entries and the receipt scope does not see them. Keep the non-zero-exit
   check outside any `try`, so that its fallback is load-bearing.
   `registry_door_pool_and_billing` takes `doors` (a dict) instead of `repo`; its door and family
   logic is unchanged. In `build_ledger_row` keep the signature `(spec, receipt, *, tier)` and get
   the doors from `base_registry_doors(spec["repo"], spec["base_commit"])`. In `write_ledger_row`
   keep the line `row = build_ledger_row(spec, receipt, tier=tier)` byte-identical (an existing
   test mutates it), then call
   `validate_row(row, door_names=frozenset(base_registry_doors(spec["repo"], spec["base_commit"])))`.
   Say in a comment that the door names also come from the base commit, so a worker-edited
   registry cannot reject the row.
