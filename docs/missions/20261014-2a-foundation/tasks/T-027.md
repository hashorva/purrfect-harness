## Objective

1. `schemas/ledger-row.schema.json` (`schema_version` 1) with every field of proposal section 8:
   mission, feature, task, run_id, parent_run, group_id, attempt, repair_round; cli, cli_version, door, pool, billing_class; requested_model, resolved_model, observed_model; effort; fast_state; task_class_tags; allow_list_size; task_text_tokens; ste_flag; active_lesson_ids; experiment_id; wall_time_s; turns; tool_calls; tokens_input, tokens_output, tokens_cache, tokens_reasoning; cost; quota_share; checks; diff_size; scope_result; anti_gaming_flags; failure_class; escalation_reason; outcome.
   Every number is `{"value": <number|null>, "source": "observed"|"estimated"|"unknown"}`
   (`value` null iff `unknown`); `cost` adds `currency`; `checks` is a list of
   `{"name", "exit_code"}`; `diff_size` is `{"files": N, "lines": N}` (both numbers with
   source flags); model fields use the same value/source pair with text values.
2. `scripts/ledger.py validate <file>` (no third-party modules): exit 0 for a valid row, 1 with
   `ERROR: ledger: <field>: <reason>` otherwise. Unknown keys are rejected.
3. Fixtures `tests/fixtures/ledger/good-*.json` (a completed run and a failed run) and
   `bad-*.json` (missing field, number without source, `observed` with null, extra key).
4. New `tests/test-ledger.py`, wired into `tests/run-tests.sh`; add `scripts/ledger.py` and the
   schema to the manifest ownership lists.
