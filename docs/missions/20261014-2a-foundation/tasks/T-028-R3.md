## Objective

**Why this task exists.** T-028-R2 added a rule that refuses 32 or more hex characters in a row. The test value for the classic GitHub token pattern, `"ghp_" + "A"*36`, is all hex after
its prefix, so the new rule now catches it too: deleting the `ghp_` pattern no longer fails any test, and a real classic token (mixed case, not hex) would then be caught by nothing.
The Architect's T-028 review required this guard before F005 acceptance; the code is sound, the tests are not.

1. **`ghp_`:** change the test value so that **only the `ghp_` pattern** can catch it: `ghp_` followed by 36 mixed-case letters and digits that are not a run of 32+ hex characters
   (include letters outside a-f, for example `Z`, `q`, `x`, and break any hex run with a non-hex letter at least every 20 characters). Built at run time from fragments. Same for **`github_pat_`**.
2. **One-pattern guard:** add a test that, for each such hostile value, **exactly one privacy rule matches** (use the validator's own pattern list or helper; if none is exposed, test through the CLI by
   removing nothing: assert via a copy of the rule with that single pattern disabled that the value is accepted). The goal: a future broad rule cannot silently hide a narrow one again.
3. **Missing tests:** one test for each of U+200C, U+200D, U+200E and U+200F (zero-width and directional marks the task of T-028-R2 named), and one for an **upper-case UUID** in a field that is not an id field.
4. **Count:** the task of T-028-R2 asked for at least 40 distinct hostile values; the worker had 27, each placed in two fields. Bring the distinct hostile values to at least 40 (built at run time), each in at least two fields.
5. Each new test must fail when its check is removed: prove it once per group in a **temporary copy** of `scripts/ledger.py` (never in the live tree) and record one line in the PROGRESS entry. Do not weaken or remove any existing test. Change no code.
