## Objective

**Why this task exists.** The Architect's review of T-028 passed the rule for what it covers (380 hostile values rejected) and listed what it does not cover. The
committed ledger must stay clean: F005 step 3 says a row containing a "secret-like string" fails. Extend the rule in `scripts/ledger.py` so that a row is refused when any
text value (any field, any nesting level, lists included) contains:

1. an **absolute path**: a value containing `/Users/`, `/private/`, `/var/folders/`, `/home/`, or a Windows drive path such as `C:\`;
2. a **UUID-shaped string in a text field that is not one of the row's own id fields** (the run id, parent run and group id fields legitimately hold UUIDs; read the
   schema for which fields those are; every other text field must not contain a UUID shape);
3. a **bearer token** (`Bearer ` followed by a token), or a **long hex or base64-like token**: 32 or more hex characters in a row, or 40 or more base64-alphabet characters in a row;
   check that no legitimate field of a good fixture is caught (model names such as `claude-haiku-5-5` and `Composer 2.5`, seat names, run ids in id fields, short reasons must still pass);
4. **hidden or look-alike characters**: zero-width characters (U+200B to U+200F, U+2060, U+FEFF), the full-width `＠` (U+FF20) and full-width solidus `／` (U+FF0F),
   and the line and paragraph separators U+2028 and U+2029;
5. **prompt-prefix variants**: a text value that starts with `Read ` followed by a path-like word, `You are `, or `Follow AGENTS.md` (the existing rule covers only the one prefix it names);
6. **no unknown key name in an error**: when a row has a key the schema does not know, the error must say that an unknown key was found (and at which level) but must
   **not print the key's name**, because the name itself could be an email address or a secret. Add a test with a key built at run time from fragments.

7. **Convert the existing secret-shaped literals** in `tests/test-ledger.py` (the seven T-028-R1 tests: the `ghp_`, `github_pat_`, `AKIA`, `xoxb-`, `-----BEGIN` and JWT values) to the **same values built at run
   time from fragments**, so no fake secret remains as one literal in the file. The tests must keep testing exactly the same hostile values (this weakens nothing); the last verification command greps the file
   for secret-shaped literals and must find none. Reason: GitHub push protection refused to push the commit that added the old literal.

Not covered, and to be documented in a comment above the rule (do not try to solve it): a secret split across several fields.

Tests (in `tests/test-ledger.py`): at least 40 hostile values built at run time, spread over different fields (`failure_class`, `escalation_reason`, task class tags, check names, model names,
nested fields), every one rejected with `ERROR: ledger: <field>: privacy` and the value absent from stdout and stderr; every legitimate value listed in point 3 still accepted; each of points
1 to 6 has at least one test that fails if that part of the rule is removed (prove it once per point in a **temporary copy** of `scripts/ledger.py`, never in the live tree, and record one
line per point in the PROGRESS entry). Do not weaken or remove any existing test. Change nothing else in `scripts/ledger.py` and no other script.
