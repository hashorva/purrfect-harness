## Objective

Owner decision (2026-10-15): extend the privacy rule in `scripts/ledger.py` that decides what may enter a ledger row.

1. **Paths:** refuse any string value containing `/tmp/`, `/etc/`, `~/` or `$HOME` in addition to the existing absolute-path prefixes
   (`/Users/`, `/private/`, `/var/folders/`, `/home/`, a Windows drive). A bare relative repository path such as `scripts/ledger.py` stays allowed.
2. **Bidirectional controls:** refuse U+202A-U+202E and U+2066-U+2069 (add to the hidden-character rule, which already covers U+200B-U+200F, U+2060, U+FEFF, U+FF20, U+FF0F, U+2028, U+2029).
3. **Bearer:** the `Bearer` token rule becomes case-insensitive (`bearer x`, `BEARER x`, `BeArEr x`) and also matches a tab as the separator.
4. **Tests** (`tests/test-ledger.py`): for each new refusal at least two hostile values, each placed in two different fields (build values at run time from fragments):
   `/tmp/x`, `~/x`, `$HOME/x`, `/etc/passwd`, each of U+202A-U+202E and U+2066-U+2069 (one test each, 14 values), `bearer abc`, `BEARER abc`, `bearer\tabc`.
   Also add one **allowed** case that must still validate: the relative path `scripts/ledger.py` in a check label.
   Each new group of tests must fail when its rule is removed: prove it once per group in a **temporary copy** of `scripts/ledger.py` (never the live tree) and record one line per group in the PROGRESS entry.
5. Do not weaken or remove any existing rule or test. Error messages must still never print the refused value.
6. Commit as `feat(ledger): refuse /tmp, ~/ paths, bidi controls and any-case bearer in rows`.
