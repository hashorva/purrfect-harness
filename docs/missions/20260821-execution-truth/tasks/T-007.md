## Objective

Make the real worker wrapper consume only the mission-owned approved `fleet.json` built
by `scripts/fleet_state.py`. Remove mutable inventory, fallback, and per-run override
authority from worker model resolution without adding any F003–F005 policy.

### Frozen resolution contract

- Map worker provider/tier to the existing canonical mission seat names:
  `agent -> cursor.<tier>`; `codex`, `agy`, and `claude -> <provider>.<tier>`.
- Default tier remains premium for agent and economy for other providers. Default speed
  remains standard for agent and unknown otherwise. Existing default effort remains
  medium.
- Resolve `$MISSION/fleet.json` through the shared `fleet_state.py resolve` command
  before constructing the ExecutionSpec or invoking any provider.
- Add a mission-path equality assertion to the shared resolver and pass the inferred
  mission path from the wrapper. A copied fleet whose embedded mission path differs must
  fail before spec persistence/provider launch.
- Provider, effort, and speed are equality assertions against the frozen seat. An
  explicit `--model` is also only an equality assertion; it may confirm the frozen model
  but can never replace it. The model written into the ExecutionSpec must be the model
  returned by the frozen resolver.
- Missing, malformed, noncanonical, unapproved, wrong-mission, missing-seat, provider,
  model, effort, or speed mismatch must exit nonzero before provider launch.
- Remove dispatch-time generation/reading of `.tasks/fleet-inventory.json` and all
  inline fallback/model-selection policy from `spawn-worker.sh`. Live inventory changes
  after freeze must be irrelevant.
- Use Bash arrays and JSON parsing only; no `eval` and no duplicated fleet policy.

Do not add mission status/Gate lifecycle checks, task/feature identity enforcement,
clean-worktree checks, workspace locks, cross-repository rejection, expanded receipt
outcomes/deltas, VerificationRecords, or feature acceptance. Those remain F003–F005.

### Mounted regressions

Extend the real wrapper integration fixture and installed-harness entry tests so every
successful worker invocation has a canonical approved read-only fleet fixture.

Add entry-point cases proving:

1. all eight provider/tier mappings launch the exact frozen model/effort/speed;
2. a matching explicit `--model` succeeds only as an assertion;
3. missing, malformed, unapproved, wrong-mission, missing-seat, and every configuration
   mismatch reject before the provider sentinel and before ExecutionSpec persistence;
4. an arbitrary changed `.tasks/fleet-inventory.json` cannot alter a successful dispatch;
5. changing the frozen file's model after one successful run is unnecessary: the
   read-only/no-clobber guarantee remains owned by the reviewed freeze policy.

Guard proof: temporarily make the wrapper consult `.tasks/fleet-inventory.json` instead
of mission `fleet.json`, then separately bypass explicit-model equality assertion. Run
`bash tests/run-tests.sh`; each mutation must fail at the mounted wrapper/fleet checks.
Restore exact bytes before the positive run. Permanent tests must not rewrite tracked
production files.
