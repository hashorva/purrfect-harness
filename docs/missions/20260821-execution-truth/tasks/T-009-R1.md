## Objective

provider exits normally, whether that exit is zero or nonzero. The real worker wrapper
must not return or publish its terminal receipt while a descendant from that run remains
alive.

Decisions are fixed:

- Preserve all ExecutionSpec v2, ExecutionReceipt v1, wrapper, lock, outcome, timeout,
  interruption, and scope contracts. Do not change schemas or add verification state.
- Correct the shared `terminate_tree()` behavior in `scripts/execution_runner.py`. A
  completed direct parent is not proof that its process group is empty; signal the
  run's process group even when `process.poll()` is already non-null. Treat an absent
  group as already clean, retain bounded TERM-then-KILL behavior, and reap the direct
  provider process when needed.
- Add two mounted real-entry regressions. In one, the provider spawns a long-lived child
  and exits 0; in the other it spawns a long-lived child and exits nonzero. In both,
  invoke the real `scripts/spawn-worker.sh`, assert the wrapper's expected exit and exact
  valid terminal receipt outcome, and prove the recorded child is no longer alive after
  wrapper return.
- Add a mutation/non-vacuity proof that restores the reproduced early-return behavior,
  observes both mounted regressions fail, then restores the exact corrected bytes.
- F004 remains `passes: false`. This correction produces implementation evidence only;
