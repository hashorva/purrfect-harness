## Objective

Mount one fail-closed Phase 1 dispatch policy in both real wrappers. Worker launches
require an in-progress mission, an approved frozen fleet, an exact task/feature/work-unit
binding, the repository root as workspace, a clean Git tree, and the exclusive workspace
lock. Brain mission-init/gate0 launches are draft-only; brain review is limited to
in-progress or awaiting-gate and uses the approved frozen `brain` seat. The lock must
remain held until the terminal receipt has been written.

Decisions are fixed:

- Cross-repository worker execution is disabled: an external `--repo` fails before
  ExecutionSpec persistence and provider launch.
- `fleet.json` approval is the mechanical Gate 0 authorization for worker and review
  dispatch. Draft mission-init/gate0 cannot require a fleet that does not yet exist.
- Existing GOAL/features/task files remain the lifecycle and identity sources; do not
  add a mutable dispatch state artifact.
- The shared policy is dependency-free Python 3 and reuses the canonical provider
  capability matrix rather than duplicating it.
- Lock acquisition is atomic and token-owned. A conflicting or orphaned lock fails
  closed; this task does not add lease expiry or recovery automation.
- Every negative fixture invokes the real wrapper and proves the provider sentinel was
  not called and no ExecutionSpec was persisted.
- F003 remains `passes: false`; verification and acceptance are deferred to F005.
