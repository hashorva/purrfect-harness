# Task: Produce strict terminal execution receipts

## Before you write any code

1. Read `AGENTS.md`, the newest 3 mission progress entries, F004 in `features.json`,
   `git log --oneline -10`, and establish a green baseline.
2. Read `.agents/skills/dispatch-worker/SKILL.md` and
   `.agents/skills/guard-verification/SKILL.md` in full.
3. This task is orchestrator-owned because it replaces duplicated lifecycle logic in
   both real launch wrappers; do not dispatch `spawn-worker.sh` to edit itself.

## Objective

Make every launched brain or worker attempt produce exactly one UUID-keyed terminal
ExecutionReceipt tied to exact immutable authorization bytes. Capture attributable
Git-visible before/after state, commits, changed paths, write-scope result, safe
invocation evidence, timestamps, and process outcome. Strict receipt validation must
be mounted in the real mission verifier.

Decisions are fixed:

- Preserve existing persisted ExecutionSpec v1 readability. New wrapper runs construct
  ExecutionSpec v2, whose only contract addition is a validated non-empty `write_scope`.
- Worker write scope is parsed before launch from the binding `Files you MAY touch`
  task section and copied into the immutable spec. Brain scope is role/action policy:
  draft mission-init/gate0 may write only within the mission directory; review may
  write only that mission's `PROGRESS.md`.
- Git attribution relies on F003's clean-tree and same-repository invariants. Capture
  exact HEAD plus a digest/count of porcelain status before and after; derive commits
  and changed paths against the authorized base commit. The stated guarantee is only
  Git-visible change inside the declared workspace.
- Use one dependency-free Python lifecycle runner for brain and worker. It owns provider
  launch, timeout, interruption, process-tree termination/reaping, outcome mapping, and
  final receipt creation. Shell wrappers retain authorization and lock ownership.
- Terminal outcomes are exactly `completed`, `failed`, `timed_out`, `interrupted`, and
  `launch_failed`. Receipt failure is a hard wrapper failure, never a silent fallback.
- Receipt identity is `.tasks/receipts/<run_id>.json`, written atomically with no-clobber.
  Timestamps are metadata and never filenames or selectors.
- Safe invocation evidence contains executable/configuration and an argv digest, not a
  second copy of the prompt or arbitrary environment values. Observed configuration
  remains literal `unknown` unless the provider actually proves it.
- Strict verification uses exact mission/run/spec identity. Timestamp-named legacy
  receipts, waivers, suffix mission matches, untagged feature fallback, missing logs,
  null worker deltas, malformed receipts, bad hashes, and scope failures cannot satisfy
  a new run. Do not create a VerificationRecord or acceptance state; that is F005.
- F004 remains `passes: false`; implementation evidence is not acceptance evidence.
