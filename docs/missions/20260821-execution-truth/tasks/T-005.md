## Objective

Finish the F001 implementation layer by making every real brain and worker provider run
use the reviewed T-004 contract. This task does not accept or flip F001; that remains
deferred until F005 can issue a fresh authorized VerificationRecord:

```text
spawn-brain.sh | spawn-worker.sh
        -> execution_spec.py create/persist
        -> immutable .tasks/specs/<run_id>.json + exact SHA-256
        -> execute_provider.py --spec ... --sha256 ...
        -> write-receipt.sh linked to the same run/spec bytes
```

Keep one provider grammar only: `scripts/execute_provider.py`. After this task neither
spawn wrapper may contain provider argv construction, provider-specific prompt ordering,
or `eval`; they may retain role-specific prompt creation, model selection, watchdog/log
ownership, and receipt handling.

Extend `scripts/execution_spec.py` with one shared construction command used by both
wrappers. It accepts the already-resolved role, mission, feature/null, work unit, attempt,
provider, model, effort, speed, canonical repo, and prompt; resolves the exact current
Git commit; generates a fresh lowercase UUID; validates; atomically persists; and prints
only machine-readable `run_id`, path, and exact-byte SHA-256. Do not duplicate JSON/spec
policy in either shell wrapper.

Wrapper CLI contract:

- Both real wrappers accept `--provider codex|claude|agent|agy`, `--model`, `--effort`,
  `--speed`, and positive `--attempt`. Worker positional provider remains supported and
  must equal `--provider` if both are supplied. Defaults: effort `medium`; speed `standard`
  for agent and `unknown` for other providers; attempt `1`.
- Worker spec identity comes from the actual task basename/work unit, `--feature`, active
  mission path, selected provider/model/configuration, current workspace, and exact prompt.
- Brain spec identity uses role `brain`, JSON-null feature, action as work unit, selected
  provider/model/configuration, mission, current repo, and exact prompt. Keep `waiver` as
  a clearly labeled non-provider legacy record; it is not an execution run and receives
  no fabricated ExecutionSpec.
- Brain defaults remain Claude/Opus only when no provider/model is explicitly selected.
  A real Sol brain must be expressible exactly as `--provider codex --model gpt-5.6-sol
  --effort high --speed unknown`; never infer provider from a model string.
- Existing worker model resolution may remain until F002 freezes fleet, but the resolved
  concrete model—not a family guess—must be persisted before launch.
- Persist the spec before invoking the shared adapter/provider sentinel. Any construction,
  validation, hash, or capability failure exits before the sentinel.
- Preserve the approved snapshot re-exec at the top of `spawn-worker.sh`; this task is the
  Gate-0-approved self-edit exception. Preserve the portable watchdog and close the outer
  worker process stdin as defense in depth, although the shared adapter also uses DEVNULL.

Extend `scripts/write-receipt.sh` compatibly:

- New provider runs pass `--run-id`, `--spec`, and `--spec-sha256` as an all-or-none trio.
  Recompute the exact file-byte hash through the shared Python policy and require the
  run ID/path/spec role/mission/work-unit/provider/model to match the receipt inputs.
- New receipts include `run_id`, `execution_spec_path`,
  `execution_spec_sha256`, requested configuration from the immutable spec, resolved
  configuration derived by importing the shared provider adapter, and observed model,
  effort, and speed as literal `unknown` until a provider proves them. Never infer observed
  values from argv, aliases, or model strings.
- Legacy direct test receipts may omit the entire trio temporarily; a partial trio or any
  mismatch fails. F004/F005 will remove legacy receipt permissiveness and migrate filenames.

Add focused deterministic integration tests mounted by `tests/run-tests.sh`:

- Stub every provider and assert exact argv plus empty explicit env overrides through both
  real spawn wrappers, not only by calling the adapter. Include the original brain Claude
  prompt-swallow reproduction and real Codex/Sol brain selection.
- For each successful stub run, locate its new spec and receipt and prove UUID identity,
  exact-byte SHA-256 linkage, role/work-unit/feature/configuration, observed `unknown`, and
  that the spec existed before the sentinel recorded invocation.
- Delete one required field from a persisted-looking spec and invoke the real shared launch
  entry; prove the sentinel is untouched. Corrupt a persisted spec after construction and
  prove the original hash rejects it.
- Unsupported effort/speed through each real wrapper fails before its sentinel. A duplicate
  run ID cannot overwrite the first spec; an amendment creates a different UUID.
- A receipt with a partial trio, wrong run ID, wrong spec path/hash, wrong role/mission/work
  unit/provider/model, or noncanonical bytes is rejected.
- Temporarily bypass wrapper use of the shared adapter and separately bypass receipt hash
  validation; run the mounted entry point and observe failure, then restore both exactly.

Do not add dispatch-status, Gate-0, clean-worktree, fleet-freeze, cross-repo, lock, expanded
Git delta, terminal-outcome, or VerificationRecord policy here; those belong to F002–F005.
