### Mission-owned frozen fleet

Expose these reviewed commands from `fleet_state.py` (argument spelling may be slightly
different only if the tests and help make the contract equally unambiguous):

```text
freeze  --mission-dir DIR --inventory FILE --bindings FILE
        --approved-by TEXT --approved-at RFC3339
resolve --fleet FILE --seat NAME
        [--provider ASSERT] [--model ASSERT] [--effort ASSERT] [--speed ASSERT]
validate-inventory FILE
validate-fleet FILE
```

`bindings` is a small JSON map from mission seat name to an inventory seat plus explicit
requested effort and speed. The freeze command derives provider/model/health/source from
the validated inventory, records its exact-byte SHA-256, and writes canonical
`docs/missions/<mission>/fleet.json` with:

- `schema_version: 1`, exact mission path/identity, inventory hash/probe timestamp;
- machine-readable approval (`status: approved`, non-empty `approved_by`, RFC3339
  `approved_at`);
- each approved seat's provider, exact model, effort, speed, health/source, and the
  provider capability values needed to reject unsupported configuration later.

Freeze is atomic, UUID-free, read-only, and no-clobber: a second call may not replace an
existing mission fleet, even with different live inventory. Phase 1 amendments require a
future explicit human workflow; do not invent it here. `resolve` consumes only the frozen
file, rejects missing/malformed/unapproved state or missing seats, and treats optional
provider/model/effort/speed arguments as equality assertions—not override authority.
It prints one machine-readable resolved binding and never reads live inventory.

Add exact JSON Schemas for machine inventory and mission fleet under `schemas/`, make
the shared validator enforce their important invariants without a third-party package,
and add the new policy/schema files to manifest install/update ownership. The real
install and update tests must prove they propagate.

### Mounted negative regressions

Add focused deterministic tests mounted by `tests/run-tests.sh`, using PATH/HOME stubs
and the public fleet entry points:

1. Successful observed provider inventory followed by a failed/empty probe preserves
   that provider's last-good record exactly, records the new failure separately, and
   resolves its seats as degraded `last_good`, never healthy observed.
2. A first-run failed probe may expose a documented fallback only as degraded/unknown;
   an empty value cannot satisfy model or approval validation.
3. Corrupt existing inventory, partial provider state, invalid timestamp/hash, extra
   fields, or noncanonical fleet bytes fail without overwriting trusted files.
4. Approved freeze records the exact inventory hash, canonical bindings, and read-only
   bytes. A second freeze cannot overwrite it; changing/reprobing live inventory after
   freeze leaves resolution unchanged.
5. Missing fleet, unapproved approval, missing seat, wrong provider/model/effort/speed
   assertion, unsupported capability, or guessed healthy source all fail closed.
6. Temporarily bypass last-good retention and separately make `resolve` consult mutable
   inventory; invoke the mounted public entry and observe failure, then restore exactly.
