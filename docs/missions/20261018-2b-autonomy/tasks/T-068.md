## Objective

1. New `scripts/usage_report.py`. It is read-only: it never writes, creates, renames or deletes a file.
   - Options:
     - `--projects DIR`, default `Path.home() / ".claude/projects"`;
     - `--tasks-dir DIR`, default `.tasks`;
     - `--repo DIR`, default the current directory;
     - `--since TIME` and `--until TIME`;
     - `--json`.
     A TIME is an ISO 8601 date or date-time read with `datetime.fromisoformat`; a naive value is UTC and a date means midnight UTC. A value that does not parse prints a message starting `usage_report: ` to stderr and exits 2.
   - Input: every `**/*.jsonl` under `--projects`, in sorted path order. It skips an unreadable file, a line that is not a JSON object, and a line without a string `sessionId`.
   - Window: a line counts only when its own `timestamp` parses and falls in `since <= timestamp < until` (each bound optional). A line without a parseable timestamp never counts, and the file's date plays no part.
   - Session class, decided per `sessionId` over all of its lines whatever their time; the first rule that matches wins:
     1. `harness`: the session id is the `session_id` of a `type: system`, `subtype: init` line in `<tasks-dir>/logs/<run_id>.log`, for the `run_id` of any `<tasks-dir>/receipts/*.json`. A session also counts as `harness` when the `message` (as JSON text) of one of its `user` lines contains a receipt's run id.
     2. `front_desk`: a line of the session has a `cwd` equal to `--repo` or inside it. Both paths go through `os.path.realpath` first.
     3. `other`.
   - Tokens: each in-window `assistant` line with a `message.usage` object counts once per (`sessionId`, `message.id`); a line without `message.id` counts alone. Its four usage fields are added to the row for (class, `message.model`, or `unknown`); a value that is not an integer counts as 0. The row's `messages` goes up by 1, and its `total` is the sum of the four fields.
   - Front Desk numbers, taken from in-window `front_desk` assistant lines:
     - `turns`: the counted messages whose line is not `isSidechain: true`.
     - `polling_calls`: `tool_use` blocks, each counted once per block `id`, that are polling. A block is polling when any of these holds:
       - its name is `Monitor`, `BashOutput` or `TaskOutput`;
       - its name is `Bash` and the stripped `input.command` matches `\bsleep\b` (sleep loops and sleep-then-check), `\btail\s+-\w*[fF]` or `\bwatch\s`;
       - its name is `Bash`, the command equals an earlier in-window Bash command of the same session, and it matches `\.tasks/|git status|\bps\b|\bpgrep\b|\btail\b|\bjobs\b`. That is a repeated status check; repeating a test command is not polling.
     - `accepted_tasks`: the number of distinct `task` values among `<tasks-dir>/events.jsonl` lines with `event` `review` and `verdict` `PASS` whose `at` is in the window. The T-066 loop writes these after a passing verification.
     - `tokens_per_accepted_task`: the `front_desk` totals summed over models, integer-divided by `accepted_tasks`; `null` when that is 0.
   - Output:
     - `--json` prints `json.dumps(data, indent=2, sort_keys=True)`. `data` has these keys:
       - `since` and `until`: ISO strings or `null`;
       - `rows`: sorted by class, then model; each row has `class`, `model`, `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `total` and `messages`;
       - `front_desk`: `turns`, `polling_calls`, `accepted_tasks` and `tokens_per_accepted_task`.
     - Without `--json` it prints a table:
       - the header `| class | model | input | output | cache write | cache read | total | messages |`;
       - the line `|---|---|---|---|---|---|---|---|`;
       - one row per entry, in the same column order;
       - a blank line;
       - `Front Desk: <turns> turns, <polling_calls> polling calls, <accepted_tasks> accepted tasks, <tokens_per_accepted_task, or n/a> tokens per accepted task`.
2. `harness-manifest.json`: `scripts/usage_report.py` goes right after `scripts/plan_extract.py` in both `install_payload_paths` and `update_paths`.
3. Frozen fixtures under `tests/fixtures/usage-report/`: hand-written and committed, never copied or generated from a real home. Paths in them use `/fixture/...` and never `/Users/`, `/home/` or `/private/var/`. The files are:
