## Objective

`python3 scripts/planning_stats.py compare <before.json> <after.json> <data> [<data> ...]` exits 0 only when F001's target is met. Each `<data>` is a ledger (`docs/missions/ledger.jsonl`) or a routing-data file, read the way T-002 and T-004 read them.

1. Interface this task relies on: `batch_rows(batch_path, data_paths)` returns the batch's runs as a list of `{"ref", "parent_total", "subagent": {"calls", "tokens", "source"}, "outcome"}`. It raises `PlanningStatsError` for a batch that T-004's `batch` refuses (not exactly 10 runs, a duplicate, an unclean run). `parent_total` is the T-001 total. If T-004 committed the same reader under another name or shape, add `batch_rows` as a thin wrapper over it; do not change T-004's behaviour.
2. `compare_reports(before, after, reviews)` (pure; lists of row dicts as above; `reviews` rows need only `ref` and `subagent`). It returns the failure messages, in this order, and `[]` when all four conditions hold. `median` is T-001's.
   1. `m = median(after parent_total)`. If `m >= 1000000`: `after median parent total <m> is not under 1000000`.
   2. A batch's parent-plus-subagent median is `median(parent_total + subagent.tokens)`. It is unknown when any of its rows has `tokens` that is not an `int`. If the before value is unknown: `before median parent-plus-subagent total is unknown`. If the after value is unknown: `after median parent-plus-subagent total is unknown`. If both are known and `after >= before`: `after median parent-plus-subagent total <a> is not below before <b>`.
   3. For every after row, then every review row, in order, whose `subagent.calls` is not an `int >= 1` or whose `subagent.source` is not `observed`: `<ref>: subagent calls <calls> source <source>; need at least 1 observed` (Python `str()` of each value).
   4. `done` = rows whose `outcome` is `done`. If `after_done * len(before) < before_done * len(after)`: `after done rate <after_done>/<len(after)> is below before <before_done>/<len(before)>`.
3. `read_review_runs(path)`: the after batch file must be a JSON object whose `review_runs` is a list of distinct canonical run ids, checked with `run_id.validate_run_id`. Otherwise raise `PlanningStatsError("after batch: review_runs must be a list of distinct canonical run ids")`. An empty list is allowed.
4. `review_rows(run_ids, data_paths)`: for each id, the rows across `data_paths` whose `run_id` equals it. There must be exactly one, else `PlanningStatsError(f"review run {run_id}: {n} rows")`. Return `[{"ref": run_id, "subagent": <that row's subagent field via T-002's reader, as {calls, tokens, source}>}]` in input order.
5. `main`: the `compare` subcommand takes `before`, `after` and one or more data paths. It calls `read_review_runs(after)` first, then `batch_rows(before, data)`, `batch_rows(after, data)` and `review_rows(review_runs, data)`, then `compare_reports`. It prints `compare<TAB>pass` and returns 0, or prints one `compare<TAB>fail<TAB><message>` line per failure and returns 1. On `PlanningStatsError`, `OSError`, `UnicodeDecodeError` or `ValueError` it prints `planning_stats: <reason>` to stderr, prints nothing to stdout, and returns 2. Existing commands keep their behaviour.
6. Create `docs/missions/20261018-2b-autonomy/batches/README.md` (at most 15 lines). It covers four things:
   - **Batch file:** one JSON object. Its planning-run list uses the keys T-004 defined (exactly 10 clean `claude.brain-planning` runs).
   - **`review_runs`:** `f001-after.json` adds it, holding the run id of every claude review run in the same window. The before file may omit it.
   - **Collecting the after batch:** the Front Desk writes `f001-after.json` from the first 10 clean planning runs after T-005 was accepted. Each of those runs starts from the prompt that `python3 scripts/brain_prompt.py planning <mission> --provider claude` prints.
   - **Running the check:** the exact `compare` command over `docs/missions/ledger.jsonl` and `docs/missions/20261014-2a-foundation/routing-data.jsonl`, its 0/1/2 exit meanings, and that it is a local-only check (like 2A F001 step 5).
