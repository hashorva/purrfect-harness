## Why each check exists

This is the F000 acceptance run. Every F000 step, as implemented in T-010..T-016, is covered by an executable assertion or the test that implements it.
1. **The oracle** fails on base `HEAD` because the F000 note is missing from `MODEL_ROUTING.md`. It also checks the note sits right after the F013 note.

   - **Discovery (T-013):** `run-tests.sh` globs `tests/test-*`.

     - uppercase
     - braced
     - urn-prefixed
     - trailing newline
     - leading space
     - nil
     - version 0
     - wrong variant
     - non-string values

     All five Python callers use it.
   - **Lessons (T-015):** the promoted rule lines are verbatim in `AGENTS.md` and the skills, and `AGENTS.md` has no `{{` consumer placeholder.
   - **2A PROGRESS (T-016):** the file opens with the FROZEN line, and its status block names every 2A feature with `passes: true`.

4. `test-ci-workflow.py` pins the matrix rows, the step order and the suite's Python header.
5. **Discovery behaviour:** the runner is copied into a temp tree with one passing and one failing `test-*.py`.
   - It runs both in sorted order and exits non-zero.
   - With only the passing test left, it exits 0.
6. `test-evidence-2a.py` audits the committed 2A evidence in a full-history clone.

8. `shellcheck`, the full suite, the clean tree and the absence of `__pycache__` are standing checks.
