## Objective

A run's token count is input + output + cache read, the run's own total (subagent messages excluded), as its stream reports it.

1. `scripts/observe_output.py`: add `stream_tokens(provider, event, seen)`, the tokens one parsed stream event adds (provider names as `observe` accepts them, including `agent`):
   - claude: an `assistant` event whose `parent_tool_use_id` is null and whose `message.id` is a string not yet in `seen` (add it) adds `message.usage` `input_tokens + output_tokens + cache_read_input_tokens`; a claude `result` event adds 0 (it repeats the total).
   - codex: `turn.completed` adds `usage` `input_tokens + output_tokens + cached_input_tokens`.
   - cursor: `type: result` adds `usage` `inputTokens + outputTokens + cacheReadTokens`.
   - agy: `event: result` adds `result.usage` `input_tokens + output_tokens + cache_read_tokens`.
   - A missing or invalid count (per `count`) adds 0; every other event adds 0.
2. `scripts/execution_runner.py`:
   - `BUDGET_EXIT = 121`; `WORKER_TOKEN_BUDGETS = {"small": 150000, "medium": 400000, "large": 800000}`.
   - `token_budget(spec, task)`: brain: 400000 when `spec["work_unit"] == "review"`, else 1000000 (mission-init, gate0, plan; these equal `brain_prompt.BUDGETS`, but the runner does not import `brain_prompt`). Worker: the `size:` value in the front matter (between the first two `---` lines) of `Path(spec["repo"]) / task`; `medium` when the file is unreadable, has no front matter or no `size:`, or names another value.
   - In `run`: compute `limit` before launch. While the provider runs, each time the log grows, read the new bytes through a second read handle that starts at `log_offset`, parse each complete line as JSON (keep a trailing partial line for the next read; skip lines that do not parse) and add `stream_tokens` for each dict event. Over `limit` the run continues. When the total exceeds `2 * limit`, stop exactly like the stall branch: `terminate_tree(process)`, outcome `"budget_exceeded"`, `exit_code = BUDGET_EXIT`, and the log note `BUDGET: <used> tokens exceed twice the token budget of <limit>; run stopped` written where the stall note is written, then break.
   - After the observation: when its `usage` `input`, `output` and `cache` values are all observed, `used = max(used, their sum)`.
   - Pass `token_budget={"limit": limit, "used": used, "overrun": max(0, used - limit)}` to `write_receipt`.
   - `build_ledger_row`: when the receipt has `token_budget`, the row gets `"tokens_overrun": observed_number(<overrun>)`.
3. `scripts/execution_receipt.py`: `OUTCOMES` gains `budget_exceeded`. Add `RECEIPT_OPTIONAL_FIELDS = frozenset({"token_budget"})`: a v2 receipt holds every field of `FIELDS` and may also hold `token_budget` (the existing error message stays). `build_receipt(..., token_budget=None)` adds it when given. When present it must be an object with exactly `limit` (int ≥ 1), `used` (int ≥ 0) and `overrun` (int equal to `max(0, used - limit)`), bools refused, else `fail("token_budget is invalid")`. Outcome `budget_exceeded` requires `token_budget` with `used > 2 * limit`, else `fail("budget_exceeded outcome requires usage over twice the token budget")`.
4. `scripts/ledger.py`: `OUTCOMES` gains `"budget_exceeded"` as its last item; `"tokens_overrun"` joins `FIELDS` right after `"tokens_reasoning"`, joins `OPTIONAL_FIELDS`, and is checked with `number_flag`.
5. `schemas/execution-receipt.schema.json`: append `budget_exceeded` to the outcome enum; add `token_budget` to `receiptBody.properties` (object, `additionalProperties: false`, required `limit`, `used`, `overrun`, all integers, `limit` minimum 1, the others minimum 0), not required. `schemas/ledger-row.schema.json`: append `budget_exceeded` to the outcome enum; add `tokens_overrun` as a `numberFlag`, not required.
6. Prompts state the budget (T-063 text plus this):
   - `scripts/brain_prompt.py` Budget section: `f"{BUDGETS[role]} tokens for this run (input + output + cache read, your own total); the runner records an overrun in the receipt and stops the run past twice the budget.{log}"`.
   - Worker prompt (the `PROMPT=` line of `scripts/spawn-worker.sh`, `CODEX_PROMPT=` in `tests/run-tests.sh`, `prompt_worker` in `tests/test-execution-integration.py`): the Budget sentence becomes `Budget: the task's max_attempts and long-command rule, and a token budget by the task's front-matter size (small 150000, medium 400000, large 800000 tokens; medium when unset); the runner records an overrun in the receipt and stops a run past twice its token budget, a stalled run or an overlong one.`
7. `docs/missions/templates/WORKER_TASK.template.md`: add `size: medium` after `max_attempts: 2` in the front matter.
8. Tests:
   - `tests/test-observe-output.py`: `test_stream_tokens_counts_each_top_level_message_once`: a repeated claude message id counts once; a claude subagent message and a claude `result` add 0; one counting event each for codex, `agent` and agy.
   - `tests/test-execution-integration.py`: the outcome parity test's expected tuple and runner regex gain `budget_exceeded`. Add `test_token_budget_overrun_is_recorded_and_twice_the_budget_stops_the_run`. It writes a fake `claude` into `self.bin`. For `FAKE_MESSAGES` rounds, the fake prints the same top-level assistant event twice (message id `msg_<i>`, usage `input_tokens` = `FAKE_TOKENS`, other counts 0) and one subagent assistant event (`parent_tool_use_id` set), flushes, and sleeps 0.3 s.      - Case 1, `FAKE_TOKENS=250000 FAKE_MESSAGES=2`: exit 0; outcome `completed`; `receipt["token_budget"] == {"limit": 400000, "used": 500000, "overrun": 100000}`; ledger row `tokens_overrun == {"value": 100000, "source": "observed"}`; `scripts/execution_receipt.py validate --receipt` exits 0; `execution_receipt.validate_receipt(<copy with overrun 0>, None)` raises `ReceiptError`.
     - Case 2, `FAKE_TOKENS=300000 FAKE_MESSAGES=3 FAKE_HANG=1 SPAWN_WORKER_TIMEOUT_SECS=20`: exit 121; outcome `budget_exceeded` and `exit_code` 121; `token_budget` used 900000 and overrun 500000; the log holds `BUDGET: 900000 tokens exceed twice the token budget of 400000; run stopped`; the receipt validates; the ledger row outcome is `budget_exceeded`; `validate_receipt` refuses a copy whose `token_budget` is `{"limit": 400000, "used": 800000, "overrun": 400000}`.

   - `tests/test-ledger.py`: the schema test treats `tokens_overrun` like `subagents` (not required; allowed besides the section 8 fields).
