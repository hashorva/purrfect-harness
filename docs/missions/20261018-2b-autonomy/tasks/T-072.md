# Task: Receipts carry the token figures and a role tag (owner items 2 and 3, receipt part)

Plan tags: category `receipt`, size `S`, review `argon` or `grok`. After T-071 (it imports `TOKEN_FIGURE_FIELDS`). No adapter argv change.
New receipts may carry two fields:
- `observation.tokens`: the seven figures of T-071;
- `role_tag`: `plan`, `review`, `gate` or `worker`, or `brain` for any other brain action.

Both are optional, so every existing receipt keeps validating. T-074 makes the runner fill `observation.tokens`.

## Objective

1. `scripts/execution_receipt.py`:
   - Add `role_tag(role, work_unit)`. A worker gets `worker`. A brain gets `plan` for `plan`, `planning` and `mission-init`; `review` for `review`; `gate` for `gate` and `gate0`; and `brain` for anything else.
   - `OBSERVATION_OPTIONAL_FIELDS` gains `tokens`. When `tokens` is present, `validate_observation` checks that it is a dict whose keys equal `TOKEN_FIGURE_FIELDS`, with each value a sourced count (the same check the `usage` fields get).
   - `RECEIPT_OPTIONAL_FIELDS` gains `role_tag`. `build_receipt` always writes `role_tag` from the spec's `role` and `work_unit`. `validate_receipt` refuses a present `role_tag` that differs from `role_tag(role, work_unit)` of the receipt.
2. `schemas/execution-receipt.schema.json`: add an optional `role_tag` (an enum of the five tags) and an optional `observation.tokens` (the seven keys, each in the sourced-count shape of the usage fields, no extra keys).
3. `tests/test-execution-receipt.py`: add `test_token_figures_and_role_tag_are_optional_and_checked` to `ExecutionReceiptObservation`. It covers the oracle's cases, checks that a receipt with neither field still validates, and checks that a receipt whose `role_tag` disagrees with its role is refused.
4. Commit as `feat(receipt): optional token figures and role tag on receipts (T-072)`.
