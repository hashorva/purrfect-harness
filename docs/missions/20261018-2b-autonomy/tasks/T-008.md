## Objective

`python3 scripts/replay_seeded_defects.py --fleet <fleet.json> --seat <name> [--seat <name> ...] --out <dir>` replays every case on every named seat. It exits 0 only when each seat catches every case its family caught in 2A. The Front Desk's real run names every reviewer seat, for example `--fleet docs/missions/20261018-2b-autonomy/fleet.json --seat brain --seat brain_argon --seat brain_codex --seat cursor.premium --seat agy.premium --out .tasks/seeded/f001`.

## Why each check exists

- The oracle fails on the base because the script has no CLI yet (it exits 0 with no table). After the change it drives the script with a fake reviewer CLI and checks:
  - every seat sees every case, in its own clone, through the real adapter argv;
  - the prompt is the T-005 review prompt (Budget 400000, explorer named for claude) plus a request that does not reveal the plant;
  - a miss that 2A did not require does not fail the run, while a required miss or an uncovered 2A family does;
  - the default required set is T-007's frozen fixture (B is required for grok), while `--routing-data` really replaces it (with a grok-A-only file, a B miss passes);
  - a bad seat stops before any launch;
  - the manifest carries the script, and the script never names a live `routing-data.jsonl`.

  Every expected row comes from the frozen fixture or a temporary file, so the oracle cannot drift as the 2A routing data grows.
- The named methods are the same checks in the suite; the whole file keeps T-007's checks green.
- The run-id scan keeps the script free of private run-id parsing.
- shellcheck, the full suite, clean tree, no `__pycache__`: standing checks.
