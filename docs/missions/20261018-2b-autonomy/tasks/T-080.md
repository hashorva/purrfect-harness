# Task: CI result for a commit decided by a script from gh output (owner item 6d, CI part)

Plan tags: category `verification`, size `S`, review `argon` or `grok`. After T-077 (both edit `harness-manifest.json`). No adapter argv change.
A gate needs CI to be green on its commit, and today a person reads the result. `scripts/ci_status.py` decides it from `gh run list` output, either live or saved. Tests use saved output only; no test calls `gh`.

## Before you write any code

1. Context: `scripts/plan_extract.py` (a small stdlib script in the house style); `install_payload_paths` and `update_paths` in `harness-manifest.json`; the gate steps in `docs/missions/ORCHESTRATION.md` (grep `CI`). Do NOT read `docs/missions/20261014-2a-foundation/progress-archive/`.
2. Baseline: skip it; the oracle (first verification command) is the check, and it fails on base.
3. You are the dispatched worker. Do not launch another worker or brain.

## Objective

1. New `scripts/ci_status.py` (stdlib, mode 100644).
   - Arguments: `--commit SHA`, which must be 40 lowercase hex characters (otherwise exit 2), and an optional `--runs-json FILE`.
   - Input: without `--runs-json`, it reads the stdout of `gh run list --commit SHA --json databaseId,name,workflowName,status,conclusion,headSha --limit 50`. A missing `gh` or a non-zero `gh` exit gives exit 2. The input must be a JSON list of objects (otherwise exit 2).
   - Decision: runs whose `headSha` differs from SHA are ignored. The result is `pass` when at least one run is left and every remaining run has `status` `completed` and `conclusion` `success`. Otherwise it is `fail`.
   - Output:
     - on pass, `CI PASS: <n> runs for <first 12 of SHA>`;
     - on fail with no runs left, `CI FAIL: no runs for <first 12 of SHA>`;
     - on any other fail, one line per failing run: `CI FAIL: <name> <status>/<conclusion or none>`;
     - in every case, a last line `json.dumps({"commit": SHA, "result": ..., "failing": [names in input order]})`.
   - Exit 0 on pass and 1 on fail.
2. `harness-manifest.json`: add `scripts/ci_status.py` to both path lists.
3. `docs/missions/ORCHESTRATION.md`: the gate step that asks for green CI now says the answer is `python3 scripts/ci_status.py --commit <sha>` exiting 0, never a reading by eye.
4. New `tests/test-ci-status.py` (unittest), class `CiStatus`, covering the oracle's cases from the fixtures `tests/fixtures/ci-status/green.json`, `red.json`, `pending.json`, `other.json` and `empty.json`.
5. Commit as `feat(verify): CI status for a commit decided from gh output (T-080)`.

Expected size: about 110 changed lines. The cap is 150.
