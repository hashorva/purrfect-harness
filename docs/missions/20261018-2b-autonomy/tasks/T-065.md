## Objective

`.tasks/events.jsonl` is the event log the Front Desk and `scripts/mission-run.sh` (T-066) read instead of polling: one JSON object per line, appended, never rewritten. A run's completion is its process exit; its `run_exit` line is the record of it.

1. `scripts/execution_runner.py`:
   - Add `append_event(repo, log, event)`: it builds `json.dumps({"at": now(), **event}, separators=(",", ":")) + "\n"`, opens `artifact_directory(repo) / "events.jsonl"` with `os.O_WRONLY | os.O_APPEND | os.O_CREAT` (mode `0o644`) and writes the encoded line with one `os.write` call (one O_APPEND write per line keeps lines from concurrent writers whole). On `OSError` or `SpecError` it appends `WARN: event not written` to the run log (itself ignoring `OSError`) and returns; an event never changes a run's outcome or exit code.
   - `main`: new option `--seat` (default `unknown`).
   - `run`: right after `before = capture_before(...)`, set `event = {"run_id": spec["run_id"], "role": spec["role"], "seat": args.seat, "work_unit": spec["work_unit"]}` and append `{"event": "run_start", **event}`. Right after `write_receipt(...)` returns, append `{"event": "run_exit", **event, "exit_code": exit_code, "outcome": outcome, "receipt": f".tasks/receipts/{receipt.name}"}`.
   - The provider's environment gains `PURRFECT_RUN_ID` (the spec's run id) and `PURRFECT_EVENTS` (the absolute path of `events.jsonl`), after `env_overrides`. `PURRFECT_EVENTS` is needed because a plan run's Claude process starts in a scratch clone, whose own `.tasks/` is discarded.
   - Decision, tested: a failed launch (`launch_failed`, exit 127) still has a receipt, so it gets both lines. A run refused before `capture_before` (spec digest mismatch, bad log path) has no receipt and writes no event. Every `run_start` therefore has exactly one `run_exit`, written after its receipt exists.
2. `scripts/spawn-worker.sh`: the runner call gains `--seat "$FLEET_SEAT"` after `--tier "$TIER"`. `scripts/spawn-brain.sh`: the runner call gains `--seat "$SEAT"` after the `--idle-seconds` value. Nothing else changes in either file.
3. `.claude/settings.json`: add a top-level `"hooks"` object after `"permissions"`, written with `json.dumps(..., indent=2)` plus a final newline: `{"SubagentStop": [{"hooks": [{"type": "command", "command": <CMD>}]}]}`, where `<CMD>` is exactly:
   `[ -n "${PURRFECT_RUN_ID:-}" ] && [ -n "${PURRFECT_EVENTS:-}" ] || exit 0; jq -cn --arg run "$PURRFECT_RUN_ID" '{at: (now | todate), event: "subagent_stop", run_id: $run, agent: ((try input catch null) | .agent_type? // null)}' >> "$PURRFECT_EVENTS"`
   With no `PURRFECT_RUN_ID` (the Front Desk's own interactive session, or any session not started by the runner) it exits 0 and writes nothing. `agent` is the payload's `agent_type` when Claude Code sends one, else `null`. The SubagentStop event and its `agent_type` field come from the Claude Code hooks documentation; no committed capture shows them yet, so the line never depends on the field and no test runs a live CLI.
4. `tests/test-execution-integration.py`:
   - The stub provider's `invoked.json` gains `'purrfect': [os.environ.get('PURRFECT_RUN_ID'), os.environ.get('PURRFECT_EVENTS')]`.
   - Add `test_run_events_pair_start_and_exit_and_skip_runs_without_receipt` before `test_zero_turn_output_turns_a_completed_run_into_a_failure`. With a codex fleet that includes the brain seat and status `in-progress`, it dispatches a worker that exits 0, one with `PROVIDER_EXIT=7`, one whose `codex` binary is removed with `PATH=/usr/bin:/bin` (exit 127; the stub is restored afterwards) and one `spawn-brain.sh docs/missions/fixture review`. It checks: the events are exactly `run_start, run_exit` four times in order; the first worker's `invoked["purrfect"]` is `[<first run id>, <resolved events path>]`; the `(role, seat, exit_code, outcome)` of the exits are `("worker", "codex.economy", 0, "completed")`, `("worker", "codex.economy", 7, "failed")`, `("worker", "codex.economy", 127, "launch_failed")`, `("brain", "brain", 0, "completed")`; each start and its exit share `run_id`, `role`, `seat` and `work_unit`, the start's `at` is not later than the exit's, and the exit's `receipt` is `.tasks/receipts/<run_id>.json` and exists. Then it runs `scripts/execution_runner.py` on the first run's spec with `--spec-sha256` of 64 zeros and the run's log: exit 125 and still 8 lines.
   - Add `test_subagent_stop_hook_appends_only_inside_a_harness_run`: it reads the one SubagentStop hook from the repository's `.claude/settings.json` (`ROOT`, not the fixture) and runs its command with `bash -c`, the payload `{"hook_event_name": "SubagentStop", "agent_type": "explorer"}` on stdin and an environment with every `PURRFECT_*` variable removed, four times: with nothing added, with only `PURRFECT_EVENTS`, and twice with both variables (a fixed UUID run id).
