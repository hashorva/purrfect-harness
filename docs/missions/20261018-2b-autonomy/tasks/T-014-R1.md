## Objective

There is one run-id rule: a canonical lowercase RFC 4122 UUID, version 1 to 8, not nil. One function holds it. A non-canonical input is refused, not lowercased, so one run can never have two file names. This is already the rule in `execution_spec.py`, `ledger.py` and `verification_record.py`, so every historic spec, receipt and ledger row still validates. Only `reconstruct_run.py` gets stricter: it refuses the nil UUID and versions 9 and up.

1. Create `scripts/run_id.py` with exactly this content:

   ```python
   #!/usr/bin/env python3
   """The one run-id rule shared by every harness CLI: a canonical lowercase RFC 4122 UUID, versions 1-8."""
   import re
   import uuid

   # Shape only, for privacy scans of free text. It never decides whether a run id is valid.
   UUID_SHAPE = re.compile(r"[0-9A-Fa-f]{8}-[0-9A-Fa-f]{4}-[0-9A-Fa-f]{4}-[0-9A-Fa-f]{4}-[0-9A-Fa-f]{12}")
   MESSAGE = "run_id must be a canonical UUID"


   def validate_run_id(value):
       """Return value unchanged when it is a canonical run id, else raise ValueError.

       Call it before the value reaches any path. The message never echoes the value.
       """
       if not isinstance(value, str):
           raise ValueError(MESSAGE)
       try:
           parsed = uuid.UUID(value)
       except ValueError:
           raise ValueError(MESSAGE) from None
       if (parsed.int == 0 or parsed.variant != uuid.RFC_4122
               or parsed.version not in range(1, 9) or str(parsed) != value):
           raise ValueError(MESSAGE)
       return value
   ```
