## Why each check exists

- The oracle fails on the base in three ways:
  - `verify()` calls `exists()` on `<mission>/verification/../../../../tmp/x.json` before refusing, so the spy list is not empty.
  - `run_records(mission, "*")` globs and fails with `invalid number: <other run's file>`.
  - The wrappers and `verification_record.py` exit 1, or with `--run-id ""` fall into audit mode, instead of exiting 2 with the run-id message.
  
  After the change it proves that every library entry refuses before any filesystem call, and that every CLI exits 2 with an exact message that never echoes the value.
- The named `test-verification-record.py` and integration tests are the regression net for real verify, accept, record numbering and the guard mutations that target this file.
- shellcheck, the full suite, clean tree, no `__pycache__`: standing checks.
