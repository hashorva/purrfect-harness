## Objective

`python3 scripts/plan_extract.py <run-id-or-log> <out-dir>`, run from the repo root, writes the task files in a plan run's final answer and prints each task id. It runs nothing else.

1. Create `scripts/plan_extract.py`, stdlib only, with shebang and docstring like `scripts/run_id.py`. It imports `observe_output` and `run_id` from its own directory. It must not contain the words `subprocess`, `os.system` or `uuid.UUID(`, not even in comments.
   - **Source.** If `run_id.validate_run_id(arg)` accepts the first argument, the log is `.tasks/logs/<arg>.log` under the current directory. Otherwise the argument is a log path.
     - The final text is the first non-None `observe_output.final_answer(p, raw)` for `p` in `("claude", "agy", "codex")`. Cursor uses claude's format.
     - Only that text is parsed. Header lines such as `prompt: ...` are never parsed: they are not JSON events.
     - If there is no final text, refuse.
   - **Out-dir.** It must be an existing directory named `tasks` whose parent holds `GOAL.md`. The mission folder is that parent, resolved; otherwise refuse.
   - **Block styles.** Scan the final text line by line.
     - *Fenced block.* It opens on a line matching `^` + four backticks + `[A-Za-z0-9_-]*$` and closes on the next line that is exactly four backticks. A fence that never closes is refused.
     - A fenced block whose first line is `---` is a task block. Its target is `<out-dir>/<task_id>.md`. A fenced block that does not start with `---` is ignored.
     - *FILE block.* It opens on `=== FILE: <path> ===`. Its body runs to the next FILE line, a line `=== END FILE ===`, or the end of the text.
     - The path must be relative. It is resolved against the current directory, with symlinks followed, and must land strictly inside the mission folder. It must not be the mission's `GOAL.md`, `features.json`, `fleet.json` or `PROGRESS.md`.
   - **Front matter.** Every task body (both styles) starts with a `---` front matter that holds `task_id: <id>`, with `<id>` matching `^T-\d{3,}(?:-R\d+)?$`. A body with no or a bad task_id is refused.
   - **Content.** A file's content is its body lines, with trailing blank lines removed, plus one newline.
   - **Duplicates and existing files.** Refuse a task_id or a target that appears twice, and a target that already exists (never overwrite). Refuse a text with no task block.
   - **All or nothing.** Validate every block before writing anything. A refusal writes nothing, prints nothing to stdout, prints `plan_extract: <reason>` to stderr and exits 2. On success, create missing parent directories inside the mission folder, write the files, print each task_id on its own line in text order, and exit 0.
2. `harness-manifest.json`: add `"scripts/plan_extract.py"` once to `ownership.install_payload_paths` and once to `ownership.update_paths`, each right after `"scripts/planning_stats.py"`.

A helper builds a temp tree with `docs/missions/fx/GOAL.md` and `tasks/`, wraps a fixture's text into a temp log line `{"type": "result", "result": <text>}`, and runs the CLI with `sys.executable` (cwd = the temp tree, `PYTHONDONTWRITEBYTECODE=1`).

     - `test_both_block_styles_are_extracted_in_text_order`: both files, their exact content, stdout `T-801\nT-802\n`.

## Why each check exists

- **Oracle.** It fails on the base because `scripts/plan_extract.py` does not exist. All its inputs are inline (backticks are built with `chr(96)`). After the change it proves:
  - both block styles are extracted in order with exact content, and a `json` block is ignored;
  - a fenced task inside the prompt header is never extracted;
  - each of these is refused and writes nothing: three traversal forms (parent segments, absolute path, symlink), a protected mission file, a missing task_id, a bad task_id, a duplicate across styles, an existing file, an unclosed fence, no blocks, and a non-tasks out-dir;
  - a run id reads `.tasks/logs/<id>.log` with an agy answer;
  - both manifest lists carry the script;
  - the script runs nothing.
- **Each `PlanExtractTests.<method>`** checks the same properties on the committed fixtures.
- **`test-run-id.py`** enforces that run ids are checked only through `run_id.py`.
- **JSON validation:** the manifest changed.
- **shellcheck, the full suite (it installs the payload), clean tree, no `__pycache__`:** standing checks.
